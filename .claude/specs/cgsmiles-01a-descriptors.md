# CGsmiles bonding descriptors in the SMILES IR (link 01a)

## Summary

Teach `molrs/src/io/smiles/` to represent and round-trip CGsmiles/BigSMILES bonding descriptors (`[$]`, `[>]`, `[<]`, `[!]`, with optional alphanumeric labels and an out-of-bracket bond order) as first-class IR data, behind a **separate fragment dialect** with its own entry points. After this link a caller can parse `[$]COC[$]` with `parse_fragment_smiles`, convert it with `fragment_to_atomistic` into a heavy-atom graph *plus* the descriptor→atom map that links 01d (pairing) and 02b (port creation) consume, and write it back with `write_fragment_smiles`. The plain SMILES surface is untouched and stays strict: `parse_smiles`, `validate_smiles`, `to_atomistic`, `write_smiles` and the registered `SmilesReader` all **refuse** descriptor-bearing input with a named error that points at the fragment entry point, so no `.smi` line can silently lose a descriptor. No pairing, no `[!]` semantics, no fragment bodies — those are 01c/01d.

## Domain basis

Sources: DOC = cgsmiles.readthedocs.io syntax pages; REF = github.com/gruenewald-lab/CGsmiles @ 910c9ee `file:line`; BIG = Lin, T.-S. et al., *BigSMILES: A Structurally-Based Line Notation for Describing Macromolecules*, ACS Cent. Sci. **5**, 1523–1531 (2019), DOI 10.1021/acscentsci.9b00476; INFERENCE as marked. (The CGsmiles paper, JCIM 2025, DOI 10.1021/acs.jcim.5c00064, was unreadable and is cited by no rule below.)

- **R4.1** Four descriptor operators, each in square brackets attached to an atom/node: `[$]`, `[>]`, `[<]`, `[!]`; any may carry an alphanumeric label: `[$a]`, `[<a]`, `[>a]`, `[$1]` [DOC fragments].
- **R4.2** A descriptor binds to the node written immediately before it; a descriptor written before any node binds to the first node of the body: `[$]COC[$]` puts `$` on atom 0 and atom 2; `[>]CC[<]c1ccccc1` puts `>` on atom 0 and `<` on atom 1 [REF read_fragments.py:140-158, verified].
- **R4.3** One node may carry several descriptors, forming an ordered list in written order: `[>][$1A]COC[<]` → atom 0 carries `['>', '$1A']`, atom 2 `['<']`; valency is not checked [DOC; REF verified].
- **R4.4** The bond order of a descriptor is written OUTSIDE the bracket, adjacent to it, on both sides of the junction: `{[#A][#B]}.{#A=CC=[$],#B=[$]=CCC}` yields a C=C of order 2 across the boundary [DOC fragments; REF read_fragments.py:148-157, verified]. BigSMILES instead puts the bond character inside (`[<=1]`) [BIG] — must not be accepted silently.
- **R4.5** The reference concatenates the order digit onto the descriptor string and recovers it as `int(desc[-1])`, lossy for aromatic order (`"$1.5"` → 5); model the descriptor as a struct {kind, label, order}, never a string; an explicit aromatic descriptor order (`c:[$]`) is rejected [INFERENCE].
- **R4.8** BigSMILES restricts labels to positive integers; CGsmiles widens them to alphanumerics [BIG; DOC].
- **R4.14** (consumed by 01d, constrains this link's representation) The bond formed when two descriptors pair takes the descriptor's annotated order, except 1.5 (aromatic) when both endpoint atoms are aromatic [REF resolve.py:350-356]. molrs's own SMILES builder applies the Daylight rule (`smiles/to_atomistic.rs:252-256`): promotion to aromatic happens **only when no bond symbol was written** — an explicit `-` between two aromatic atoms stays single (biphenyl). The descriptor therefore has to distinguish "no symbol written" from "`-` written", which is why `order` is an `Option`.
- **R4.17** Unconsumed descriptors at the atomistic level are filled with hydrogen in a later repletion step [DOC chirality; REF resolve.py:431-433] — which is why the *fragment* path may hand unpaired descriptors back to the caller as data, while the plain SMILES path must refuse them.

Compatibility/pairing (R4.6–R4.16) are 01d; `[!]` semantics and its RAISE are 01c — here `DescriptorKind::Shared` is merely representable.

**Spec-local disambiguation (INFERENCE, recorded because R4.4 alone does not settle it).** A bond character *preceding* a descriptor bracket is always that descriptor's order (`CC=[$]` → order 2). A bond character *following* a descriptor bracket is the descriptor's order **only** when the descriptor is a leading descriptor of its chain, i.e. no atom of that chain has been parsed yet (`[$]=CCC` → order 2 on atom 0, then C–C–C single). Mid-chain, a bond after a bracket is an ordinary bond to the next atom (`C[$]=CC` → `$` with no written order on atom 0, C0=C1 double). Without this rule `C[$]=CC` is ambiguous; with it both R4.4 junction forms parse deterministically. The leading form is strictly less expressive than the trailing form ("no written order on the head **and** a double bond to the next atom" is writable as `C[$]=CC` but not in leading form) — recorded here and in the parser docs, and the reason the writer emits only the trailing form. This inference is a decision to be recorded through `/mol:note` by the orchestrator, not by the implementation.

## Design

### Two dialects, one `Dialect` enum, two sets of entry points

The parser's private `ParserMode { Smiles, Smarts }` (`parser.rs:25`) and the writer's private `Mode { Smiles, Smarts }` (`smiles/write.rs:19`) model one concept twice today. This link replaces both with one `pub(crate) enum Dialect { Smiles, Smarts, FragmentSmiles }` in `chem/` (the shared-vocabulary module), consumed by parser and writer, so the third variant lands in one home rather than silently in two. Nothing public changes: both enums were private.

The public surface gains one entry point per stage, each the fragment-dialect sibling of an existing plain-SMILES one, with a consistent infix qualifier:

| plain SMILES (unchanged, strict) | fragment dialect (new) |
|---|---|
| `parse_smiles` | `parse_fragment_smiles(text) -> Result<SmilesIR, SmilesError>` |
| `to_atomistic` | `fragment_to_atomistic(&SmilesIR) -> Result<(Atomistic, Vec<(AtomId, BondingDescriptor)>), SmilesError>` |
| `write_smiles` | `write_fragment_smiles(&SmilesIR) -> Result<String, SmilesError>` |

These are **not** dual names for one symbol (`Naming`, `architecture-rules.md`): they accept and emit a strictly different language and return different types. Each is documented as "a SMILES **fragment body** with CGsmiles/BigSMILES bonding descriptors", never as "a second SMILES parser", and each names its plain sibling in its `///`. The in-tree precedent is exact: `parse_smiles` (`parser.rs:43`) and `parse_smarts` (`:48`) are two names over one `Parser` dispatching on the dialect. `parse_smiles` on a descriptor bracket returns `DescriptorInPlainSmiles`, whose `Display` names `parse_fragment_smiles`; that is how the user finds the right door. Successor links 01c (fragment bodies) and 02b (`to_fragment`) call `parse_fragment_smiles` / `fragment_to_atomistic`.

Widening `parse_smiles` itself was rejected: it would leave no strict-SMILES entry in the crate, and `write_smiles` would then emit strings its own parser accepts but the SMILES standard does not.

### Representation: a field on `AtomNode`, not a `ChainElement` variant

```rust
pub struct BondingDescriptor { pub kind: DescriptorKind, pub label: String, pub order: Option<BondKind> }
pub enum DescriptorKind { Symmetric, Left, Right, Shared }   // $  <  >  !
pub struct AtomNode { pub spec: AtomSpec, pub span: Span, pub descriptors: Vec<BondingDescriptor> }
```

Both `BondingDescriptor` and `DescriptorKind` derive `Debug, Clone, PartialEq`: `AtomNode` already derives all three (`chem/ast.rs:92-93`) and now carries `descriptors: Vec<BondingDescriptor>`, so the compiler forces it, and 01e's binding clones descriptors on read (a frozen contract, like 01b's IR types).

Role names, not glyph names, matching in-file precedent (`BondKind::Single`, `Chirality::Clockwise`); each variant's `///` states its glyph, its BigSMILES/CGsmiles role **and its pairing rule** — `Symmetric` (`$`, AA-type: bonds only to another `Symmetric` of the same label), `Left` (`<`) and `Right` (`>`) (AB-type: `Left` bonds only to `Right`), `Shared` (`!`, CGsmiles squash operator) — with one upstream CGsmiles reference. The `$` glyph is overloaded with `BondKind::Quadruple` (`ast.rs:154`) and disambiguated only by bracket position; a note next to `BondKind::Quadruple` says so, so the next reader of `C$[$]C` is not surprised. `label` is a `String` (possibly empty). `order` is `Option<BondKind>`: `None` means no bond symbol was written next to the bracket, `Some(k)` means `k` was written; the effective order for pairing (01d) is `Single` when `None`. `BondKind` is reused rather than a new four-variant enum because the symbol before/after a descriptor *is* a SMILES bond token and one vocabulary keeps parser and writer in one place; the five variants that are illegal here (`Aromatic`, `Up`, `Down`, `Any`, `Ring`) are refused at the single construction site (below), so no second check is needed downstream.

**The `ChainElement::Descriptor` alternative was weighed and rejected.** Descriptors *are* written at chain positions, which is what makes an anchor rule necessary at all, so the variant is the honest-looking choice. It fails on three counts: (1) `Chain.head` is an `AtomNode`, not a `ChainElement`, so a leading descriptor (`[$]COC`, R4.2) has no slot and would need a special case anyway; (2) a branch-only descriptor `N([>])C` would put a `ChainElement::Descriptor` first in a sub-`Chain` whose `head` is mandatory and absent — the variant cannot be built there without restructuring `Chain`; (3) the four consumers would each grow a variant arm *and* re-derive the anchor, four times, at consume time. The field resolves the anchor **once, at parse time**, where written order is known.

Its cost is real and is the reason for the next section: a descriptor is invisible to the four `match &node.spec` sites, so each gets an explicit, tested decision rather than compiler silence.

### Per-site decision (every one tested)

- **`to_atomistic.rs:169` (`add_atom_node`) — one walker, one choke point, one flag.** `Builder` gains two private **owned** fields, `collect_descriptors: bool` and `descriptors: Vec<(AtomId, BondingDescriptor)>` (owned, not a borrowed `&mut Vec`: a borrowed field would add a second lifetime parameter to `Builder<'a>` and a partial move at the exit for no gain; the `Vec` is returned by value — an `Option<Vec>` was considered and rejected because the fragment path would then handle a `None` it had itself made impossible). With `collect_descriptors == false` (the plain `to_atomistic` path) `add_atom_node` rejects any node carrying descriptors with `DescriptorsUnconvertible` (whose `Display` names `fragment_to_atomistic`), exactly as `AtomSpec::Query` is rejected at `:225-231`; with `true` (the `fragment_to_atomistic` path) it pushes `(AtomId, descriptor)` for each descriptor in the atom's list, in visit order — per-atom list order at the atom's visit, **not** text position (`C(N[<])[>]` makes the two differ: the parser folds `>` onto the head carbon, which the walker visits before the branch nitrogen carrying `<`, so the map reads `>` then `<` while the text reads `<` then `>`) — and the returned map's order **is** the port order that 01d and 02b index. `.`-separated components (`SmilesIR.components`) flow through the same loop (`to_atomistic.rs:66`), so the map spans components in component order then visit order, and R4.2's leading-descriptor rule applies per component head — which is why `C.[$]` is `DanglingDescriptor`: the second component has no atom for it to bind to. `to_atomistic` and `fragment_to_atomistic` are therefore the same walker (`build_chain:128`), not two; a test asserts both produce an identical graph for descriptor-free input. Every atom — head `:133`, `BondedAtom :145`, branch recursion `:149` — flows through `add_atom_node`, and every external entry reaches this walker (`frame_reader.rs:20-25`, `perceive/aromatic_standard.rs:92-94` under `cfg(test)`, `molrs-wasm/src/smiles.rs:99`, `molrs-capi/src/frame.rs:168`), so the guard is the whole choke point: a `.smi` line `[>]COC[<]` is refused twice (parse and convert) and can never read into an `Atomistic` that lost its descriptors. `frame_reader.rs` itself is **unchanged code**; it joins the Files list only for the test that pins the surfaced error.
- **`validate.rs:54` (`validate_atom_element`) → reject; well-formedness has one home in `chem/validation.rs`.** `validate_smiles` is the plain-dialect validator, so it refuses any descriptor (`DescriptorInPlainSmiles`), symmetric with `to_atomistic`. Descriptor well-formedness is `pub(crate) fn validate_descriptor(&BondingDescriptor, span, input) -> Result<(), SmilesError>` in `chem/validation.rs` — the file that already owns shared-grammar checks (`validate_ring_closures`, `:17`) and already imports both `ast` and `error`; `chem/ast.rs` stays import-free (it has zero `use` lines today, and an `ast → error` import would close a cycle with `error.rs:5`'s `use ast::Span`). `chem/validation.rs:1-6` currently says "shared **post-parse** validation helpers used by **both** SMILES and SMARTS"; `validate_descriptor` runs during parse and serves one dialect, so that header is amended in the same edit to "grammar-level validation helpers shared across the dialects". The rule: label must be ASCII-alphanumeric or empty (R4.1/R4.8, `InvalidDescriptorLabel`); `order`, when `Some`, must be one of `Single | Double | Triple | Quadruple` (`InvalidDescriptorOrder`), so `Aromatic` (`c:[$]`) is a hard reject per R4.5 and so are `Up`/`Down`/`Any`/`Ring`. It is called at **exactly one site**: the parser, at descriptor construction. That site is the only producer of a descriptor-bearing `SmilesIR` — `from_atomistic` and `local_smarts` emit empty lists, and no binder constructs `AtomNode` values (`molrs-python/src/io/mod.rs` wraps `SmilesIR` opaquely) — so `fragment_to_atomistic` does not re-validate. A public `validate_fragment_smiles` was **not** added: zero in-tree call sites (Shape check 3).
- **`from_atomistic.rs:462/480` (and `local_smarts.rs:285,369,392`) → empty.** An `Atomistic` carries no descriptors — the graph never stored them, and a fragment's descriptors travel beside the graph in the 01d/02b map — so these sites emit `descriptors: Vec::new()` and `write_smiles(from_atomistic(mol))` is byte-identical to today. Tested for `from_atomistic`; `local_smarts` builds SMARTS query chains and is pinned by its existing round-trip tests.
- **`write.rs:79` (`write_atom`) → emits, in `Dialect::FragmentSmiles` only.** `write_smiles`/`write_smarts` on a descriptor-bearing node return `DescriptorInPlainSmiles` so their output stays parseable by their own parser. Mechanically: `match &node.spec { … }` is the tail expression returning `Ok(())` per arm, so it is rebound (`match … { … }?;`) before the descriptor loop. Emission is the canonical **trailing** form — atom, then per descriptor the written order via `write_bond_kind` (`:369`) whenever it is `Some` — **including `Some(Single)`, which emits `-`** — followed by `[` glyph label `]`; `None` emits no symbol. `Some(Single)` and `None` are different IR values (R4.14: an explicit `-` between two aromatic atoms stays single, absence promotes), so the writer must not apply its ordinary omit-default-single policy to a descriptor order; `CC-[$]` round-trips as `CC-[$]`. Because `BondingDescriptor` has public fields and `fragment_to_atomistic` does not re-validate, an externally built descriptor with an illegal order (`Some(Aromatic)`) could reach the writer and produce `c:[$]` — text its own parser rejects; the writer's descriptor branch therefore returns `InvalidDescriptorOrder` for anything outside `Single|Double|Triple|Quadruple` (it branches on `order` anyway), so the round-trip contract holds for every IR the writer accepts. **The `Dialect` merge must not widen the writer's SMARTS path:** `write.rs:144`, `:333` and `:340` guard SMARTS-only constructs (`AtomSpec::Query`; `BondQuery::Not`; `And`/`Or`) with `mode == Mode::Smiles`, which would be **false** for `FragmentSmiles` and silently emit query atoms and `!`/`&`/`,` operators into a fragment string; those three guards become `dialect != Dialect::Smarts` (or an exhaustive `match`), and two tests pin it — `write_fragment_smiles` on a `Query`-atom IR and on a `BondQuery::Not` IR must error. (The parser's `== ParserMode::Smarts` sites default `FragmentSmiles` to SMILES behaviour, which is the intent; only the writer's polarity was wrong.) The rustdoc of `write_fragment_smiles` states the contract plainly: **canonical trailing form; the input text is not preserved, the IR is** — leading-form input (`[$]=CCC`) is written as `C=[$]CC`, and a second parse+write pass is stable (the precedent is `write_smiles_ethanol_stable`).

### Parsing

`Scanner` gains `pub fn peek_next(&self) -> Option<char>` (the char one position beyond the cursor; `pub` like every other `Scanner` method — the struct is `pub(crate)`, which already bounds it; the precedent for char-level reads is `peek` at `scanner.rs:36`, while `peek_byte` (`:100`) reads the byte *at* the cursor; generalised to `n` only when a second caller appears). The descriptor lookahead — `[` followed by one of `$ > < !` — runs in **every** dialect and is then dispatched by dialect: `FragmentSmiles` accepts the descriptor; `Smiles` returns `DescriptorInPlainSmiles` (this is what makes the routing error producible — without the lookahead in `Smiles` mode the input would fall into `parse_bracket_symbol:336` and die as `UnexpectedChar('$')`); `Smarts` falls through untouched to the existing bracket-query parser, where `[$(…)]` is recursive SMARTS and `[!C]` is negation — pinned by tests `parse_smarts("[$(C)]")` and `parse_smarts("[!C]")`. Consequently `parse_smiles("[$(C)]")` and `parse_smiles("[!C]")` now fail with `DescriptorInPlainSmiles` instead of `UnexpectedChar` (both were invalid SMILES before and after); the chosen kind is pinned by a test for `parse_smiles("[$(C)]")`. `$` as the quadruple-bond character is already safe: `parse_chain` only treats it as a bond when an atom start follows (`parser.rs:93`), so `C$C` is unaffected.

The dispatch site is the three `parse_atom` call sites in `parse_chain` (`:125` head, `:144` after a bond, `:153` bare atom) plus `parse_branch` (`:166`) — **not** `parse_atom` (`:233`), whose `-> Result<AtomNode, _>` signature is unchanged, because a descriptor is not an `AtomNode`. `parse_chain` collects leading descriptors before the head atom and attaches them to it (R4.2); mid-chain descriptors attach to the current anchor — the last `BondedAtom` atom, else `head` — via one private helper, which `Branch` and `RingClosure` do not advance, mirroring `to_atomistic`'s `current`. `parse_branch` consumes any descriptor run immediately after `(` and hands it **up** to the parent anchor: `(` is not a node, so per R4.2 `N([>])C` puts `>` on N, `C([$])O` puts `$` on C, and in the mixed branch `C([>]N)C` the `>` lands on the first `C`, not on `N`; `C(=[>])C` gives the parent's descriptor order `Double`; a branch whose whole content was descriptors produces no `ChainElement` at all, and `C()` stays the error it is today. A descriptor with no anchor at all (`[$]`, `C.[$]`) is `DanglingDescriptor`. A bond character *inside* the bracket (`[<=1]` BigSMILES, `[$-]`) is `BondInsideDescriptor` — R4.4 says the order lives outside, and accepting the BigSMILES spelling silently would mean two spellings with one meaning. The leaf `parse_bracket_symbol` (`:336`) stays element-only.

### Error surface

Seven new `SmilesErrorKind` variants — `DescriptorInPlainSmiles`, `DescriptorsUnconvertible`, `BondInsideDescriptor`, `InvalidDescriptorLabel(String)`, `InvalidDescriptorOrder(BondKind)`, `DanglingDescriptor`, `AtomAnnotationUnsupported(String)` — and seven new arms in the exhaustive `Display` match at `error.rs:64-85`. `AtomAnnotationUnsupported(String)` is raised by `parse_bracket_atom` (`parser.rs:289`) in `Dialect::FragmentSmiles` only, when a `;` sits where `]` is expected after the bracket sub-parts: CGsmiles atom-level annotations — weights `[C;0.5]`, chirality `[C;1;S]`, wildcard overloading `[*;s=C,0]` — are notation this chain refuses in v1 (01c's R5.5), and the parser that already lexes the bracket is the one place to name them; a pre-scan in 01c would be a second lexer. The payload is the text between `;` and the closing `]` (or end of input), the span covers the bracket atom, and the message says the feature is unsupported rather than that the bracket is unclosed. In `Dialect::Smiles` the same input keeps returning `UnclosedBracket`, pinned by a test; `Dialect::Smarts` never reaches this code (`;` is its low-precedence AND at `:624`). The enum is public and not `#[non_exhaustive]`, so adding variants (and the new public field on `AtomNode`) is a change visible at the next minor bump; verified that every binder maps errors via `Display` (`molrs-python/src/helpers.rs:86`), that `molrs-capi`/`molrs-wasm` carry no `SmilesErrorKind` match, and that `molpack/src` names neither `SmilesErrorKind` nor `AtomNode`. No `#[non_exhaustive]` retrofit (itself breaking). No binder exposes the fragment dialect in this link.

### Reuse decision

- `Scanner` — **generalize**: add `peek_next()`; the descriptor predicate needs one byte beyond the cursor. No second cursor.
- `SmilesError` (variants-only) — **reuse**: seven new `SmilesErrorKind` variants plus `Display` arms; no new error type, no new conversion.
- `ParserMode` + writer `Mode` — **generalize into one**: `chem::Dialect` replaces both private enums; one home for "which dialect".
- `chem/validation.rs` — **reuse** as the home of `validate_descriptor` (beside `validate_ring_closures`); `ast.rs` stays import-free.
- `Builder` (`smiles/to_atomistic.rs`) — **reuse**: one walker with a private `collect_descriptors` flag and an owned collection; no second IR→graph implementation.
- `write_atom` / `write_bond_kind` — **reuse**: descriptors are emitted inside `write_atom` and their order through `write_bond_kind`; no parallel emitter.
- `perceive::smarts` — **negative pattern, stays independent**: no dependency added in either direction (verified: it never names `io::smiles` outside `perceive/aromatic_standard.rs:92` under `cfg(test)`).
- Placement: everything inside `molrs/src/io/smiles/**`, crate `molcrafts-molrs`, feature `smiles`; no new module, no new file except none.

## Testing strategy

Unit tests are inline `#[cfg(test)]` modules next to the code (`CLAUDE.md` §Testing Rules; there is no `molrs/tests/` tree and no `regressions/` tree). Every test targets one function of one module with hand-written inputs; no third-party software, no captured numbers, no multi-stage pipelines. Gate: `cargo test -p molcrafts-molrs --lib --features full,filesystem,stream` plus `cargo test --doc -p molcrafts-molrs --features full,filesystem,stream`.

**`parser.rs` — happy paths (fragment dialect).** `[$]COC[$]` → 3 atoms, descriptor on atom 0 and atom 2, both `Symmetric`, label `""`, order `None` (R4.2). `[>]NCC(=O)[<]` → `>` on atom 0, `<` on the last chain atom. `Clc[$a]c[$b]` → labels `"a"`/`"b"` on the two aromatic carbons. `[>][$1]COC[<]` → atom 0 carries `[Right, Symmetric("1")]` in written order (R4.3).

**`parser.rs` — edge cases.** `CC=[$]` and `[$]=CCC` both give order `Some(Double)` on the junction atom (R4.4), and `[$]=CCC` leaves C–C–C single. `C[$]=CC` gives order `None` on atom 0 and a double C0=C1 bond (the spec-local disambiguation above). `N([>])C` → 2 atoms, 1 bond, `>` on N; `C([$])O` → 2 atoms, `$` on C; `C([>]N)C` → `>` on the first C, not on N; `C(=[>])C` → `>` with order `Some(Double)` on the first C. `C$C` is still two atoms with a `Quadruple` bond and no descriptor.

**`parser.rs` — rejections and dialect isolation.** `parse_smiles("[$]COC[$]")` → `DescriptorInPlainSmiles`; `parse_smiles("[NH4+]")`, `parse_smarts("[!C]")` and `parse_smarts("[$(C)]")` byte-for-byte unchanged (the lookahead runs in every dialect but only `FragmentSmiles` accepts and only `Smiles` names the routing error). `[<=1]` and `[$-]` → `BondInsideDescriptor`; `[$]` alone and `C.[$]` → `DanglingDescriptor`; `[$a+]` → `InvalidDescriptorLabel`; `c:[$]` → `InvalidDescriptorOrder` (R4.5); `[C;0.5]` and `[*;s=C,0]` → `AtomAnnotationUnsupported` in the fragment dialect with the annotation text as payload, while `parse_smiles("[C;0.5]")` → `UnclosedBracket`, unchanged.

**`error.rs`.** Each new variant's `Display` renders a distinct non-empty message with the caret context, and `DescriptorInPlainSmiles` / `DescriptorsUnconvertible` name `parse_fragment_smiles` / `fragment_to_atomistic` respectively — that string is how a user is routed, so it is asserted.

**`to_atomistic.rs`.** `to_atomistic` on a fragment IR → `DescriptorsUnconvertible`. `fragment_to_atomistic("[$]COC[$]")` → 3 atoms, 2 bonds, map `[(C0, $), (C2, $)]`; for `[>][$1]COC[<]` the per-atom order is `[>, $1]`; for `C([$]O)[>]` the map order follows the walker's visit order (atom 0's descriptors in list order at atom 0's visit), not text position; for `C(N[<])[>]` the `>` entry (atom 0) precedes the `<` entry (atom 1), the reverse of text order. `to_atomistic` and `fragment_to_atomistic` produce identical graphs for descriptor-free `CC(=O)O`.

**`validation.rs` / `validate.rs`.** `validate_descriptor` accepts `("a1", Some(Double))` and rejects `("a-", None)` and `("", Some(Aromatic))`; `validate_smiles` on a hand-built descriptor IR → `DescriptorInPlainSmiles`.

**`write.rs`.** `write_fragment_smiles(parse_fragment_smiles("[$]COC[$]"))` is idempotent under a second parse+write pass and the re-parsed IR carries the same kinds, labels and orders; `[$]=CCC` writes as `C=[$]CC` and is stable from there; `C[$]=CC` is stable; `CC-[$]` writes as `CC-[$]` and re-parses with `order == Some(Single)`; `[!]C` parses to `Shared` and writes back as `[!]`; `write_smiles` on the same IR → `DescriptorInPlainSmiles`.

**`from_atomistic.rs`.** `from_atomistic` of ethanol yields `descriptors.is_empty()` on every node and an unchanged `write_smiles` string.

**`frame_reader.rs`.** `SmilesReader` over the line `[>]COC[<]` returns `Err(InvalidData)` whose message names the fragment entry point; `CCO` still reads to 3 atoms / 2 bonds (existing tests unchanged).

**Public-API example (this repo's regression-example equivalent — there is no `regressions/` tree; `CLAUDE.md` makes the rustdoc doctest the public-API gate).** `molrs/src/io/smiles/mod.rs` carries a runnable (non-`ignore`) doctest: `parse_fragment_smiles("[$]COC[$]")` → `fragment_to_atomistic` → asserts `n_atoms() == 3`, `ports.len() == 2`, both `DescriptorKind::Symmetric`. Values are hard-coded literals hand-derived from R4.2; nothing is imported or shelled out at test time. It runs under `cargo test --doc -p molcrafts-molrs --features full,filesystem,stream`.

**Docs.** Every new `pub` item (`BondingDescriptor`, `DescriptorKind` and its four variants, `AtomNode.descriptors`, `parse_fragment_smiles`, `fragment_to_atomistic`, `write_fragment_smiles`, the seven error variants) carries a `///` per `.claude/notes/docs.md` Part A Tier 1, with `# Errors` on every `Result`-returning function.
