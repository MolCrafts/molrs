# CGsmiles coarse-graph parser and IR (chain link 01b)

## Summary

`molrs::io::smiles` gains a second notation front door: `parse_cgsmiles(text)` turns a CGsmiles string such as `{[#PEO][#PEO][#PEO]}` into a `CGSmilesIR` — a list of resolution levels, each a graph of named coarse-grained nodes and typed edges, with every node and edge carrying a byte span back into the input. This link parses the coarse graph only: it reads node names, per-node annotations (partial charge `q`), 01a's bonding descriptors, the four bond symbols, branches, ring markers and the `|n` repeat operator, and it reports every malformed input as a `SmilesError` whose rendered message names the notation that was being parsed ("CGsmiles parse error at position …"). Resolving a node name to a fragment body (01c), expanding a level to atoms (01d) and the reader/writer seam (01e) are the following links; nothing here converts anything to a `MolGraph` or a `Frame`.

## Domain basis

Sources: DOC = cgsmiles.readthedocs.io syntax pages (*Basic graph description*, *Multiple resolutions*); REF = the CGsmiles reference implementation, github.com/gruenewald-lab/CGsmiles at commit 910c9ee (2026-09-14), `file:line`; INFERENCE as marked. The CGsmiles paper (Grünewald et al., J. Chem. Inf. Model. 2025, DOI 10.1021/acs.jcim.5c00064) was unreadable during this research pass and is cited for provenance only — no rule below rests on it. Rules are cited in the `cgsmiles/mod.rs` rustdoc with project + commit, never a bare file:line.

R2.1 A node is `[` `#` alphanumeric-identifier [annotations] `]` [DOC basic_graph_description]. R2.2 Two `[#A]` occurrences are two distinct node instances with the same name [REF read_cgsmiles.py:219-231]. R2.3 Adjacency in the string ⇒ edge [DOC]. R2.4 Bond-order symbols `.`→0, `-`→1, `=`→2, `#`→3, `$`→4; default 1 [DOC table; REF read_cgsmiles.py:134]. R2.5 Placement is positional: between two nodes → chain bond `{[#A]=[#B]}`; immediately before a ring marker → the ring bond `{[#A].1[#B][#C]1}` (A–C order 0, A–B and B–C order 1); between a node and `(` → the branch bond `{[#A](=[#B])[#C]}` (A=B 2, A–C 1); after `)` → the bond to the following node `{[#A]([#B])=[#C]}` (A–B 1, A=C 2) [DOC; REF verified]. Ring bond order comes from the opening marker [REF read_cgsmiles.py:160-165]. R2.6 `#` is both the node-name sigil and bond order 3; `$` is both order 4 and the descriptor sigil; disambiguation is purely positional [DERIVED; REF verified]. R2.7 `(...)` nests and attaches to the node written immediately before `(`: `{[#A][#B]([#D])[#C]}` ⇒ A–B, B–D, B–C [DOC]. R2.8 Sibling branches `{[#A]([#B])([#C])}` ⇒ A–B, A–C; nesting `{[#A]([#B]([#C])[#D])[#E]}` ⇒ A–B, B–C, B–D, A–E [REF verified]. R2.9 A bare digit after a node opens a ring marker; the second occurrence closes it: `{[#A]1[#B][#C]1}` = 3 nodes, 3 edges [DOC]. R2.10 `%`+digits is a multi-digit marker; the docstring restricts it to two digits "in agreement with OpenSmiles" while the implementation accepts arbitrary runs — enforce exactly two [REF :71-73, :157-168; INFERENCE]. R2.11 A marker number is reusable after close: `{[#A]1[#B][#A]1[#C]}` = 4 nodes, 4 edges [REF]. R2.12 Hard errors in the reference: unclosed marker at end of block ("dangling ring index"); a closure duplicating an existing edge ("You define two edges between the same node. Use bond order symbols instead.") — this forbids multigraphs [REF :336-338, :239-243]. R2.13 Any node name may carry `;symbol=value` pairs `{[#A;q=1;mass=72][#B;q=0]}` [DOC]. **R2.14 Reserved symbols, coarse node — positional order: slot 1 = fragname (the `#X` itself), slot 2 = `q`, slot 3 = `w`; `q`→charge (float, default 0.0), `w`→weight (float, default 1.0)** [DOC table; REF dialects.py:135-148]. **R2.15 Positional annotations are legal and must be parsed: `[#A;0]` ≡ `[#A;q=0]`; `[#A;0;0.5]` ≡ `[#A;q=0;w=0.5]`; `[#A;0.5]` ≡ `[#A;q=0.5]`** [DOC; REF verified]. The old molpy Lark grammar (`git -C ../molpy show a3da3f1^:src/molpy/parser/smiles/grammars/cgsmiles.lark`) cannot express this — do not port it. R2.16 Unknown symbols are retained as free key/value strings [REF dialects.py:148]. R2.17 `;` may not occur in a key or value; more than one `=` in a pair is an error [REF dialects.py:66-74]; values may not contain `]` [INFERENCE]. R2.18 Coarse-node annotations do not propagate to the atoms of the fragment [REF verified]. R2.19 `[#A]|5` ≡ five A chained by four default edges [DOC]. R2.20 `|n` after `)` repeats the whole branch **including its anchor**, successive anchors chained: `{[#A]([#B][#B])|3}` = 9 nodes, 8 edges [DOC; REF read_cgsmiles.py:93-102, verified]. R2.21 The anchor need not be the first node: `{[#A][#B]([#C])|3}` ⇒ A–B(–C)–B(–C)–B(–C), 7 nodes, 6 edges [REF verified]. R2.22 The repeated unit joins the previous copy by an order-1 edge unless a bond symbol precedes `|`, which is promoted to the anchor bond order [REF :276-282]. R2.23 `|n` after a node with more than one branch is mangled by the reference (`{[#A]([#B])([#C])|3}` yields A–B, A–C, A–B′, B′–C′, B′–B″, B″–C″) — RAISE [INFERENCE]. R1.3 The reference splits blocks with `\{[^\}]+\}`: `{}` is silently skipped there — RAISE here; `}` cannot appear inside a block [REF resolve.py:493]. R1.4 Inside a base graph `.` is bond order 0 (a virtual edge), not a component separator [DOC "Zero bond order Example: {[#A].[#B]}"]; R6.3 order-0 edges and virtual particles are RAISE in v1 — a molrs choice, not a property of the notation [DOC multiple_resolutions; INFERENCE]. R4.10 Every node of the level-k graph is instantiated as a disjoint copy of its fragment graph, **carrying its own descriptor lists** [REF resolve.py:266-315] — descriptor labels are pairing *classes* consumed one occurrence at a time (R4.13, stated in 01d's Domain basis: both descriptors of a pair are consumed after pairing and never offered again, REF resolve.py:346-348), not one-shot identities, which is why a descriptor inside a repeated unit is cloned per copy while a ring marker is not (R2.12 forbids two closures of one marker). R4.16 Edge order: the reference iterates networkx adjacency order; molrs pins **parse order** for edges and documents that ring cases therefore index atoms differently from the reference [INFERENCE]. R5.5 weight detection surface: keyword `[#A;w=0.5]` and positional third field `[#A;0;0.5]`; run after dialect binding; default 1.0 never raises [DOC; REF dialects.py; INFERENCE]. R6.1 Coarse rings are ordinary macrocycles: crown ether `{[#PEO]1[#PEO]|4[#PEO]1}` = 6 nodes, 6 edges [DOC].

Units: `charge` is a partial charge in elementary charge units `e` (`.claude/notes/science.md`), `F = f64`; it is not a formal charge — `AtomSpec::Bracket { charge: Option<i8> }` (`chem/ast.rs:109`) is the formal one, and the rustdoc says so at both sites. `weight` (R2.14) is dimensionless and unsupported when non-default in this link; bond order is the dimensionless multiplicity 1..=4.

## Design

**Placement.** A new `molrs/src/io/smiles/cgsmiles/` module (private: `mod cgsmiles;`), sibling of `smiles/` and under the same `smiles` feature gate. The CG IR types live in `cgsmiles/ast.rs` next to their single consumer — **not** in `chem/`, whose module doc (`chem/mod.rs:1-10`, `chem/ast.rs:8-11`) defines it as the vocabulary shared by SMILES and SMARTS; `BondingDescriptor` (01a) stays in `chem/ast.rs` because the fragment dialect and the CG graph both use it. `io/smiles/mod.rs` is the single public re-export path for every public CG symbol (mirroring `mod parser;` + its re-exports), so no symbol is reachable by two paths. `io` may depend on `core` + `perceive` only; this module depends on neither, so the dependency rules of `architecture-rules.md` are untouched.

**IR (`cgsmiles/ast.rs`).**

- `pub struct CGSmilesIR { pub levels: Vec<CGGraph>, pub span: Span }` — one graph per resolution. Today's invariant, stated in rustdoc **and pinned by the parse unit test** (`levels.len() == 1`; 01c deletes that assertion when it appends resolved levels). `levels` ships with the vector shape from the start because the whole chain lands in one release and renaming a public type between links is the larger churn. The struct has no public constructor and no supported mutation: it is a value produced by `parse_cgsmiles`, with public fields for reading, as `SmilesIR` is.
- `pub struct CGGraph { pub nodes: Vec<CGNode>, pub edges: Vec<CGEdge> }` — parse order in both vectors.
- `pub struct CGNode { pub name: String, pub charge: Option<F>, pub annotations: Vec<(String, String)>, pub descriptors: Vec<BondingDescriptor>, pub span: Span }`. No `instance` field: a node is addressed by its index in `levels[k].nodes`, which is what 01c's `parent: Option<usize>` and 01d's pair table use. `charge` is rustdoc'd as "partial charge in e (CGsmiles `q`, positional slot 2), not a formal charge". After dialect binding `annotations` contains neither `q` nor `w` (tested).
- `pub struct CGEdge { pub i: usize, pub j: usize, pub order: CGBondOrder, pub span: Span }`.
- `pub enum CGBondOrder { Single, Double, Triple, Quadruple }`, `#[derive(Debug, Clone, Copy, PartialEq, Eq)]` like `BondKind` (`chem/ast.rs:145`), each variant rustdoc'd with its glyph (`-`, `=`, `#`, `$`), plus `pub fn multiplicity(&self) -> u8` returning 1..=4 — the number 01d consumes as "n bonds per edge" (`ResolvedPair.bond` ranges over it). 01d is its accepted single caller: the chain ships in one release, the same argument that keeps `levels` a `Vec` now; its unit test lives here (glyph → 1..=4 table) so the method is not shipped untested. Order 0 is **not representable**; `.` raises `CgInvalidBondOrder`.
  *Why not reuse `BondKind`*: `BondKind` carries `Aromatic`, `Up`, `Down`, `Any`, `Ring` (`chem/ast.rs:144-165`), none of which mean anything between two coarse-grained beads. Reusing it would make every CG consumer match on variants that cannot occur and would let a stereo bond typecheck its way into a CG edge. `CGBondOrder` is a coarse-edge *multiplicity*; the chemistry of a resolved bond (01d) is a `BondKind` and is named `kind` there, never `order`.

**Dialect binding of annotations — the positional table is normative and tested.** Annotations are parsed as a raw ordered list of pairs; a pair with no `=` takes its key from its positional slot per R2.14: **slot 2 → `q`, slot 3 → `w`** (slot 1 is the `#NAME` itself); a fourth positional slot is `CgMalformedAnnotation`. After binding, `q` is parsed as `F` into `charge`, `w` is refused (below), and every remaining pair is retained verbatim in `annotations` (R2.16). Two tests whose expectations differ under the reversed reading pin the table: `{[#A;0.5]}` → `charge == Some(0.5)`; `{[#A;0;0.5]}` → `CgUnsupportedAnnotation { key: "w", value: "0.5" }` and `{[#A;0;1]}` → `charge == Some(0.0)` with no error (`w = 1` is the default, R5.5).

**Two refusals of valid notation, both documented as molrs v1 choices in the `cgsmiles/mod.rs` rustdoc, each naming the spec that may lift it:** order 0 (`.`, virtual edges/particles, R6.3) → `CgInvalidBondOrder`; a non-default weight `w` (R2.14/R2.15, keyword or positional) → `CgUnsupportedAnnotation { key: "w", value }`. Neither is a property of the notation; a later `cgsmiles-*` link that models virtual particles (order 0) or mapping weights (`w`, together with the pending schema-vocabulary spec) lifts them — the rustdoc names those two follow-ups so the refusal is traceable.

**Parser (`cgsmiles/parser.rs`).** A private `struct CgParser<'a> { scanner: Scanner<'a>, input: &'a str, … }` owns the parse state (node list, edge list, open ring markers, branch anchor stack, current bond); `pub fn parse_cgsmiles(text: &str) -> Result<CGSmilesIR, SmilesError>` in `cgsmiles/mod.rs` is the thin front door that constructs it and runs it. This link accepts exactly one block; text after the closing `}` raises `TrailingCharacters` (reused), tested by `second_block_is_trailing_characters` — a test that **01c deletes by name** when it lifts the restriction.

**`|n` replay and spans.** A repeated unit is re-parsed by *rewinding the same scanner* to the unit's start offset and re-scanning its byte range **within the full input**, using a new `pub fn seek(&mut self, pos: usize)` on `Scanner` (`chem/scanner.rs`; spelled `pub` like its siblings — the struct is `pub(crate)`, which already bounds it). A fresh `Scanner` over a byte slice was rejected: `Scanner::new` starts at pos 0 and `error`/`error_at` (`scanner.rs:90-97`) stamp `self.input`, so every diagnostic inside a repeated unit would carry a slice-relative position and a caret over the slice. `seek` carries a stated invariant: `pos` is **clamped** to `bytes.len()` (clamp only — no `debug_assert!`, so debug and release behave identically and the out-of-range case is testable by value), so `eat_digits`' `&self.input[start..self.pos]` can never slice out of range; every `Span` the CG parser emits satisfies `start <= end` (a backward seek never leaves a `span_from(start)` with `start > pos` because the unit's start is re-recorded after the seek); both are tested, including `seek(len + 1)` landing at `len`. The consequence is documented in `CGNode`/`CGEdge` rustdoc: replayed copies **share** the template's span, so spans in a `CGGraph` are neither disjoint nor monotonic.

**`|n` and identities inside the repeated unit.** A ring marker open **or** close inside a repeated unit raises `CgRepeatOnRingMarker` (both tested): a marker is a one-shot identity — R2.12 forbids two closures of one marker — so replaying it is either a silent overwrite or a self-bond. A bonding descriptor inside a repeated unit is **cloned into every copy** and that is correct by the notation's own semantics: a descriptor label is a pairing *class*, consumed one occurrence at a time (R4.10, R4.13), so three copies of `[$1]` are three ports of class `$1`, exactly what `{[#A]|3}` with `#A=[$1]…` denotes. The rustdoc states this asymmetry next to `CgRepeatOnRingMarker`.

**Errors — the notation is a field, not a derivation.** One error type keeps serving all three notations, but the notation being parsed is a fact owned by the entry point, so `SmilesError` gains a field `pub notation: Notation` (`pub enum Notation { Smiles, Smarts, CGsmiles }` in `error.rs`) set by the constructor the entry point uses: `parse_smiles`/`parse_fragment_smiles` stamp `Smiles`, `parse_smarts` stamps `Smarts`, `parse_cgsmiles` stamps `CGsmiles` — including the five kinds CGsmiles reuses (`UnexpectedChar`, `EmptyInput`, `TrailingCharacters`, `UnclosedBranch`, `UnmatchedRingClosure`), which a variant-name classifier could never label. `Display` (`error.rs:86`) writes `"{notation} parse error at position {pos}: …"`. The existing `test_display_with_caret` (`error.rs:116-127`) asserts only substrings and **not** the prefix, so it is not a regression guard for the prefix; this link adds the prefix assertion for SMILES, SMARTS and CGsmiles in the same task so the guard exists before it is relied on.

**Mechanism and blast radius, stated.** `SmilesError::new` (`error.rs:52`, `pub`, public fields) has **16** in-tree call sites: 2 in `Scanner::error`/`error_at` (`chem/scanner.rs:90-97`) and 14 elsewhere — `chem/validation.rs:25`, `smiles/to_atomistic.rs:94,225,242,299,326`, `smiles/write.rs:26,145,360`, `smiles/from_atomistic.rs:94`, `smiles/validate.rs:78`, `smiles/local_smarts.rs:78`. `notation` is a required constructor argument (no default — a defaulted `Smiles` would be the silent mislabel this fix removes): `Scanner::new(input, notation)` stamps it at construction (the one in-tree `Scanner::new` is `parser.rs:65`; `CgParser` constructs its own with `CGsmiles`), and the 14 non-scanner sites pass it explicitly — the parse/validate/convert paths of a SMILES IR stamp `Smiles`, the SMARTS emit paths (`write.rs:360`, `local_smarts.rs:78`) stamp `Smarts`. The `Parser` (01a's `Dialect`-driven parser) holds its `dialect` only and derives the notation by a total mapping (`Smiles | FragmentSmiles → Notation::Smiles`, `Smarts → Notation::Smarts`; `CGsmiles` is unreachable there), so there are not two homes for the fact. Consequently this link corrects the pre-existing mislabel of SMARTS *parse* errors as "SMILES" and of the SMARTS emit-path errors alike (found + fixed); no external consumer constructs `SmilesError` (checked: `molrs-python/src/helpers.rs` only formats it; no sibling repo names it), so the constructor change is in-tree churn, not an API break. The six additional files join the Files list below.

`CgInvalidRingMarker` creates a divergence in form with SMILES, which reports the identical malformed `%n` as `UnexpectedEnd` (`parser.rs:220` for `%1` with one digit, `:227` for `%` followed by a non-digit) — that SMILES mislabel is rot named here and routed with both lines to `/mol:note`; it is not fixed in this link because changing what `parse_smiles` reports for existing invalid input is a SMILES-behaviour change outside this link's contract (this link touches `parser.rs` only to stamp the notation). Reused unchanged: `UnmatchedRingClosure`, `TrailingCharacters`, `EmptyInput`, `UnexpectedChar`, `UnclosedBranch`.

**Why `parse_cgsmiles` is a free function, and what was rejected.** Shape check #1 asks for the natural owning type. The considered-and-rejected alternative is `CGSmilesIR::parse(text)` — rejected because `io/smiles/mod.rs:59-64` already exports `parse_smiles` and `parse_smarts` as free functions (and `io/reader.rs:33-38` states that per-format parsing is a stateless free function), so a third notation that spells its construction differently makes the module teach two stories at once; `CgParser` *is* the owning type, and it is private because it has exactly one user-visible step. Secondary alternative, also rejected: a `Reader`/`FrameReader` (`io/reader.rs:24-39`) — that contract is "one `Frame` at a time from a `BufRead`", and a coarse graph with no coordinates is not a `Frame`; the reader seam is 01e's scope.

**Why `Parser` / `ParserMode` is not generalized.** Not because the two notations share nothing — they share `Scanner`, `Span`, `SmilesError` and the ring-closure idea. It is because the token vocabularies overlap **adversarially**: `[#NAME]` is lexically the SMARTS atomic-number primitive `[#6]` (`parser.rs:713`), `$` is `BondKind::Quadruple` in bond position (`parser.rs:460`), and `$(` opens recursive SMARTS (`parser.rs:727`). A mode-dispatching parser would have to consult the mode at nearly every token, and a missing check would silently parse one notation as the other instead of failing. Two parsers over one scanner keeps the failure mode loud.

**Reuse decision** (resolving every `librarian_report` candidate):

- `Scanner` (`chem/scanner.rs`) — **reuse**, extended with `pub fn seek` (bounded) and notation-aware error construction.
- `SmilesError` / `SmilesErrorKind` (`error.rs`) — **reuse**, variants added, plus the `notation` field and `Display` prefix.
- `Span` (`chem/ast.rs`) — **reuse**, unchanged.
- `SmilesIR` (`chem/ast.rs`) — **pattern** only: `CGSmilesIR` mirrors its "owned nodes + spans, no graph library, public fields, no public constructor" shape; no type is shared.
- `BondingDescriptor` (01a, `chem/ast.rs`) — **reuse** verbatim as `CGNode.descriptors`' element type.
- `BondKind` (`chem/ast.rs:145`) — **new** (`CGBondOrder`): reason above.
- `Parser` / `ParserMode` (`parser.rs`) — **new** (`CgParser`): reason above.
- Placement `cgsmiles/{mod.rs,ast.rs,parser.rs}` (private module) with re-exports via `io/smiles/mod.rs:54-64` — accepted as advised, moved out of `chem/` for the reason above.

**Doc claims corrected by this link (iron law).** `io/smiles/mod.rs:1-13` says the module hosts SMILES and SMARTS only, and `:3-6` / `:21-25` assert a `parse_smarts → crate::perceive::smarts::SmartsPattern` pipeline that does not exist. **01a lands the header edit**; this link verifies during implementation that the header names CGsmiles (no test asserts doc text — source-text gates are not unit tests, `testing.md:18`) and adds the CGsmiles pipeline line and its re-exports. The `io` rows of CLAUDE.md's module table (line 189, below the `mol:bootstrap:managed end` marker) and of `architecture-rules.md` § Module ownership (line 59, no ownership marker) are factual table updates and are edited by the implementation. `.claude/notes/notes.md` is `/mol:note`'s page (CLAUDE.md § Development Workflow; entries carry topic markers), so the implementation does **not** edit it: the `/mol:impl` summary names the deferred items — (a) the two-SMARTS-parsers / two-SMARTS-ASTs duplication between `io/smiles/parser.rs` and `perceive/smarts`, (b) `parser.rs:713-726` storing `[#6]` as `AtomPrimitive::Element { symbol: "#6" }` although `Element::by_number` exists at `core/system/element.rs:1128` (the in-code "would need `Element::by_number`" rationale is stale), (c) the SMILES `%n` → `UnexpectedEnd` mislabel at `parser.rs:227`, (d) the `io::smiles` module name now denoting a notation family while containing an inner `smiles` module (`#[allow(clippy::module_inception)]` at `:43`) — and the orchestrator records them through `/mol:note`, routed to `/mol:refactor` / `/mol:fix`.

## Testing strategy

All tests are inline `#[cfg(test)]` modules next to the code (`.claude/notes/testing.md`); there is no `molrs/tests/` tree and no `regressions/` tree in this repo. One behaviour per test, hand-written inputs, hard-coded expected values, no external tool at test time or as a value source. Every raised kind is asserted by its exact `SmilesErrorKind`, never by a message substring.

**`molrs/src/io/smiles/error.rs`** — `Display` for a `Cg*` kind and for a reused kind raised by `parse_cgsmiles` both render `"CGsmiles parse error at position N"` with the caret under column N of the full input; `parse_smiles` and `parse_smarts` errors render `"SMILES …"` / `"SMARTS …"` (new prefix assertions; `test_display_with_caret` is left as is and no longer cited as the guard); one test per new kind asserting its message text.

**`molrs/src/io/smiles/cgsmiles/ast.rs`** — `CGBondOrder::multiplicity` returns 1, 2, 3, 4 for Single, Double, Triple, Quadruple.

**`molrs/src/io/smiles/chem/scanner.rs`** — `seek` back to an earlier offset re-reads the same bytes and `error()` at the re-read position reports that position in the **full** input; `seek(len + 1)` lands at `len` (clamp, asserted by value) and cannot make `eat_digits` slice out of range; a span minted after a backward seek has `start <= end`.

**`molrs/src/io/smiles/cgsmiles/parser.rs`** — happy path: F1.1 (and `levels.len() == 1`), F1.2 exact edge list `[(0,1,Single),(1,2,Single)]`, F1.3 `[(0,1,Double),(1,2,Triple),(2,3,Quadruple)]`, F1.4 four nodes / three Single edges, F1.5 `[(0,1),(0,2)]`, F1.6 ring closure emits `(0,2)` last, F1.7 `charge == Some(-0.5)` and `annotations == [("kind","ether")]` (neither `q` nor `w` present), F1.8 one `Symmetric` descriptor per node, F1.9 five nodes / both branch copies anchored on node 0 / a descriptor inside the unit on every copy, F1.11 `charge == Some(0.5)`, F1.12 `{[#A;0;1]}` → `charge == Some(0.0)`, F1.13, F1.14, F1.15 A–C edge `Double`. Rejections (exact kind each): `{}`, `{[#A;]}`, `{[#A;q=x]}`, `{[#A;w=2]}`, `{[#A;0;0.5]}` (→ `CgUnsupportedAnnotation { key: "w", value: "0.5" }`), `{[#A;x=S]}`, `{[#*;q=1]}`, `{[#A].[#B]}`, `{[#A]=}`, `{[#A]%1}`, `{[#A]1[#B]1[#A]}` (duplicate pair), `{[#A]1[#B]}`, `{[#A]|0}`, `{[#A]|x}`, `{[#A]1|2[#B]1}` and `{[#A]1[#B]1|2}` (open and close inside a repeat), `{[#A](|2[#B])}`, `{[#A]([#B])([#C])|3}`, F1.10 by the test name `second_block_is_trailing_characters`. One test asserts an error raised inside a replayed copy has `err.span.start` inside the original string's bounds and `err.input == "<full text>"`.

**Public-API example (this repo's equivalent of a regression example).** A rustdoc doctest on `molrs/src/io/smiles/cgsmiles/mod.rs` parsing F1.2 through the public path only (`use molrs::io::smiles::parse_cgsmiles;`), asserting hard-coded values — three nodes, `levels[0].edges.len() == 2`, `edges[0].order.multiplicity() == 1`. It is executed by `cargo test --doc -p molcrafts-molrs --features full,filesystem,stream`, which `--lib` does not cover.

**Domain validation.** The bond-symbol → multiplicity mapping (R2.4) and the positional slot table (R2.14/R2.15) are asserted against hard-coded values taken from the cited documentation and reference implementation; `q = -0.5` is asserted as a partial charge in e. No third-party program is imported, invoked, or snapshot.
