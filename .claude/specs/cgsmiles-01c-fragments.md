# CGsmiles multi-resolution fragment blocks (link 01c)

## Summary

`parse_cgsmiles` currently accepts a single coarse-grained block and rejects anything after it. This link teaches the reader the structural half of the notation: a string is a sequence of `{…}` blocks separated by `.`, where block 0 is the coarsest graph and every later block is a *fragment table* mapping the names used one level up to the bodies that replace them. After this link, `parse_cgsmiles` on the three-block F8 string returns a `CGSmilesIR` that carries every parsed fragment table *and* the expansion each intermediate table denotes — level 1 built by copying each fragment body once per referencing node, with `parent` back-pointers intact — while the bodies of the last block are kept as `SmilesIR` values with their bonding descriptors, not expanded into atoms. Inter-fragment bonds are still absent: descriptors are carried, not paired (01d). Notation this chain refuses in v1 — the squash operator `[!]`, atom-level `;` annotations, duplicate or missing fragment names — fails with a named `SmilesErrorKind` and a span into the original string instead of parsing into a wrong graph or being dropped the way the reference implementation drops it.

## Domain basis

DOC = cgsmiles.readthedocs.io; REF = github.com/gruenewald-lab/CGsmiles @ 910c9ee `file:line`; INFERENCE as marked. The CGsmiles paper (J. Chem. Inf. Model. 2025, DOI 10.1021/acs.jcim.5c00064) was unreadable during this research pass and is cited but not relied on.

- **R1.1** A CGsmiles string is a sequence of resolution blocks, each in `{}`, separated by `.` [DOC introduction, multiple_resolutions].
- **R1.2** Block 0 is the base graph (coarsest). Blocks 1..N are fragment lists: block k defines the bodies of the node names that appear at level k−1 [DOC multiple_resolutions].
- **R1.3** The reference splits blocks with `\{[^\}]+\}` [REF resolve.py:493]; consequences: `{}` is silently skipped there (RAISE here — 01b already does), and `}` may not appear inside a block.
- **R1.4** `.` is overloaded three ways, disambiguated by nesting depth: outside `{}` block separator; inside a CG graph bond order 0 (raises in v1); inside an atomistic body OpenSMILES disconnection (`{#OHter=[$][O-].[Na+]}` is a salt) [DOC; REF tests].
- **R1.5** The lowest resolution (last fragment block) is normally atomistic and its bodies are OpenSMILES; intermediate bodies are CGsmiles graphs over the next level's `[#X]` nodes [DOC fragments: "it is permitted to use OpenSMILES syntax to define an atomic resolution fragment"; multiple_resolutions]. The reference makes this a flag `last_all_atom=True` [REF resolve.py:261]; the syntax does not mark it. molrs v1 fixes the rule "last block = atomistic" [INFERENCE — spec decision].
- **R2.24** `|n` is legal inside a fragment body (`{#B1=[#PEO]|4}`) [REF resolve.py:155]; the reference crashes when `|n` is the last token of a body [REF read_fragments.py:210-213] — do not mirror.
- **R3.0** Fragment block grammar `{#NAME=body(,#NAME=body)*}`; splitting is on `,` first, then on the first `=` [REF read_fragments.py:251-254] ⇒ a body may not contain `,` or `}`; it may contain further `=`.
- **R3.1** "Each fragment name must be unique" [DOC fragments]; the reference keeps the first definition and silently drops later ones [REF read_fragments.py:303-304] — RAISE.
- **R3.2** A base-graph node name with no matching fragment is an error unless every incident edge has order 0 [REF resolve.py:282-287].
- **R3.3** An intermediate-level body is a CGsmiles graph over `[#X]` nodes of the next level and carries bonding descriptors beside those nodes: `{#A0=[#A1a][#A1b][>]}` [REF tests/test_layering.py:8-14].
- **R3.4** Cross-level referencing is by name only, resolved against the next block's dictionary; no scoping, no forward/backward references [REF resolve.py:402-423].
- **R4.10** Every node of the level-k graph is instantiated as a disjoint copy of its fragment graph, carrying its own descriptor lists [REF resolve.py:266-315].
- **R4.20** Each fragment block owns its own descriptor namespace, consumed at its own resolution step; descriptors in block k attach to level-k nodes and are matched when the level-(k−1) edges are resolved; never visible to other levels [REF resolve.py:402-426].
- **R5.1** Membership is implicit and positional: every atom (or child node) written in the body of `#X` belongs to the instance of `[#X]`; the reference records it as `fragid` per atom [REF resolve.py:290-300].
- **R5.2** `[!]` (squash) is the only syntax placing one atom in two beads [DOC fragments].
- **R5.5** v1 RAISE surface: the token `[!` in any body at any level; weights `w` keyword or positional (coarse third field `[#A;0;0.5]`, atomic first field `[C;0.5]`), chirality `x` (`[C;1;S]`), wildcard overloading `[*;s=C,0]` [DOC; REF dialects.py:135-148].

Fixtures used by this link:

- **F2** `{[#OH][#PEO]|3[#OH]}.{#OH=[$]O,#PEO=[$]COC[$]}` → `levels[0]` 5 nodes / 4 edges; `fragments[0] = {OH: Smiles(1 atom, 1 descriptor), PEO: Smiles(3 atoms, 2 descriptors)}`; no CG level 1.
- **F8** `{[#B1][#B2][#B1]}.{#B1=[>][#PEO][#PEO][<],#B2=[>][#PE][#PE][<]}.{#PEO=[>]COC[<],#PE=[>]CC[<]}` → `levels[0]` 3/2; `fragments[0] = {B1: Graph(2 nodes, 1 edge, Right on node 0 and Left on node 1), B2: Graph(2/1)}`; `levels[1]` instantiated = 6 nodes (parents 0,0,1,1,2,2; names PEO,PEO,PE,PE,PEO,PEO), 3 intra edges, no inter edges yet; `fragments[1] = {PEO: Smiles(3 atoms), PE: Smiles(2 atoms)}`.
- **F9 must-raise**: `{[#SC4]1[#TC5][#TC5]1}.{#SC4=Cc(c[!])c[!],#TC5=[!]ccc[!]}`; `{[#A][#B]}.{#A=[C;0.5]C,#B=CC}`; `{[#T]}.{#T=C1=CCCC[*;s=C,0][*;s=C,0]}`; `{[#A]}.{#A=CC,#A=CCC}`; `{[#A][#B]}.{#A=CC}`; `{[#A]}.{#A=CC}}`; `{[#A]}.{}`; `{[#A]}.{#A=}`; `{[#A]}.{#A=[#X]}.{#Y=CC}`; `{[#A]}.{#A=[#X][#X]}`.
- Known-bad documented string, not a fixture: the README SMA example references `[#MAH]` but defines `#MHA`.
- Reviewer-added must-raise strings (derived from the grammar above, not from DOC/REF): `{[#A][#Q]}.{#A=[#X]}.{#X=CC}`, `{[#PEO][#PEO]}[#X]`, `{[#A]}.{#A}`, `{[#A]}.#A=[$]C[$]`, `{[#A]}.{#A=CC(}`, `{[#A][!]}`; the Testing strategy enumerates the full set.

## Design

### Pipeline: syntax → instantiate → validate, one public door

`parse_cgsmiles(text) -> Result<CGSmilesIR, SmilesError>` stays the single public function for the format (no `resolve_all` / `build_everything` façade) and performs, in order: **syntax** (block split + per-block parse, `cgsmiles/parser.rs`), **instantiate** (per level *k*: `check_coverage`, then the R4.10 expansion into `levels[k+1]`, `cgsmiles/instantiate.rs`), **validate** (post-parse squash rejection, `cgsmiles/validate.rs`) and — from 01d — **resolve** (descriptor pairing, `cgsmiles/resolve.rs`). Each step is a private function in its own file, taking `input: &str` so every error it raises carries the full text, a real span and `Notation::CGsmiles`.

This consciously bends **Shape check #2** of `CLAUDE.md` ("more than one user-visible step → split into primitives"), and the reason is recorded here so it can be reconsidered: the operator ruled that port pairing is resolved **once, by the reader**, and pairing at an intermediate level is only definable over an instantiated level. An un-instantiated or unresolved `CGSmilesIR` is therefore not a state any caller may hold; exposing `parse` and `instantiate` as separate public primitives would make an illegal intermediate state representable, which costs more than the split buys. The sub-steps are not independently meaningful to any caller, in-tree or downstream, so Shape check #3 ("only one in-tree call site → do not extract") also argues against promoting them. `instantiate` is **private** — not `pub`, not a method on the public `CGGraph` — and the `CGSmilesIR` rustdoc states the invariant: *a `CGSmilesIR` that exists is fully instantiated and validated (and, after 01d, fully resolved)*. The bend is limited to this one type; nothing else in `io::smiles` gains a multi-step public call.

### Block splitting and the fragment-table grammar

Splitting is lexical, depth-aware and done by `CgParser` — which owns the `Scanner` and the input — not by a regex (R1.3): scan from depth 0, track `{`/`}` and `[`/`]` nesting, and treat `.` as a block separator **only** at depth 0. A `.` inside `{}` or `[]` is never a separator (R1.4): inside a CG graph it is the order-0 bond 01b already rejects with `CgInvalidBondOrder`; inside an atomistic body it is the OpenSMILES disconnection the SMILES parser handles (`{#OHter=[$][O-].[Na+]}` is a salt). Each block is recorded as an absolute `(start, end)` byte range into the original input, so every downstream span indexes that input. A separator not followed by `{` (`{[#A]}.#A=[$]C[$]`), or residue after the last `}` (`{[#A]}.{#A=CC}}`), raises `CgExpectedBlock` at the offending byte. Segment 0 is fed to 01b's existing base-graph path verbatim.

A fragment block's interior is split on `,` at bracket depth 0 — so `[*;s=C,0]` stays inside its entry — then each entry on its **first** `=` (R3.0); a body may contain further `=`; a `}` cannot reach a body because block splitting ends the block at the first depth-0 `}`. Errors, every one carrying the full input and a real span:

| Kind | Raised when |
|---|---|
| `CgExpectedBlock` | a separator is not followed by `{`, or text follows the last `}` |
| `CgMalformedFragmentEntry` | an entry lacks `#`, lacks `=`, or has an empty name |
| `CgEmptyFragmentBody` | `#name=` with nothing before `,` or `}` |
| `CgEmptyBlock` | `{}` in any position — 01b's variant, **reused**; the caret says which block. No `CgEmptyFragmentBlock` is introduced |
| `CgDuplicateFragment(String)` | the same name defined twice in one table (R3.1; the reference keeps the first silently) |
| `CgUndefinedFragment(String)` | a name used at level *k* is missing from table *k* (R3.2 / R3.4) |
| `CgSquashUnsupported` | a `DescriptorKind::Shared` descriptor survives to validation (R5.2 / R5.5) |
| `CgLastBlockNotAtomistic(Box<SmilesErrorKind>)` | a last-table body fails to parse as a fragment SMILES body |
| `CgBuild(String)` | an internal invariant of the reader was violated (below); 01d reuses it for its own structural failures |

All are additive variants on `SmilesErrorKind` in `io/smiles/error.rs` beside 01b's, one message arm each; the notation prefix of the rendered message comes from `SmilesError.notation` (01b), so no `Display` work beyond the arm is needed.

### `CgLastBlockNotAtomistic` boxes the inner kind; the annotation refusal has one lexer

A last-block body is parsed by `parse_fragment_smiles` over the body substring, so its error is **re-based** before it leaves this reader: the kind is preserved, `span` is the inner span shifted by the body's absolute start offset in the full input, `input` is the full CGsmiles text and `notation` is `Notation::CGsmiles` — the span contract of § Block splitting holds for last-block diagnostics too. `CgLastBlockNotAtomistic` boxes the inner `SmilesErrorKind` rather than discarding it, and its message states the molrs rule ("the last block must be an atomistic (OpenSMILES) body") followed by the inner message — so `{[#A]}.{#A=[#X][#X]}` names the rule instead of leaking a bare `UnexpectedChar('#')`. One kind **propagates un-wrapped** (kind unchanged, span re-based as above, never boxed): `SmilesErrorKind::AtomAnnotationUnsupported(_)`, which 01a's fragment dialect raises for `;` inside a bracket atom (`[C;0.5]`, `[C;1;S]`, `[*;s=C,0]` — R5.5). It is a deliberate "this notation feature is unsupported" diagnostic, not evidence that the block is non-atomistic. There is therefore **no `;`-in-bracket pre-scan** in this link: the parser that already lexes the bracket atom names the feature, and SMILES lexing has one home. It is distinct from 01b's `CgUnsupportedAnnotation { key, value }` / `CgAnnotationOnWildcard` / `CgMalformedAnnotation`, which speak about `[#X;…]` CG-node annotations; the two families never fire on the same occurrence (`[*;s=C,0]` is 01b's `CgAnnotationOnWildcard` in CG-node position and 01a's `AtomAnnotationUnsupported` inside an atomistic body). Squash `[!]` is detected structurally rather than textually (Validation below), so it is refused at every level by one rule.

### Positional, flag-free dispatch (R1.5, INFERENCE)

Dispatch is by position, with no mode flag: the **last** block's bodies go to 01a's `parse_fragment_smiles` (plain `parse_smiles` must not be called on a body — it rejects descriptors with `DescriptorInPlainSmiles`, so `{#OH=[$]O}` would fail there); every **earlier** block's body is a CGsmiles graph over the next level's `[#X]` nodes and goes to a new private **body entry point** on `CgParser` over 01b's node-sequence loop — it starts without `{` and ends at end-of-body — so positional/keyword dialect binding, the three bond-symbol positions, branches and ring markers behave identically inside a body. It is entered at the body's **absolute offset in the full input**: 01b's `|n` replay re-scans through `Scanner::seek`, so a **CG** body is never re-based into a substring scanner (last-block atomistic bodies go to `parse_fragment_smiles` over the body substring, and their errors are re-based per the next section); a body-level `CgRepeatOnRingMarker` therefore carries a span into the original string, and `|n` as a body's last token works (R2.24; the reference crashes there). Descriptors written beside `[#X]` land in that body's `CGNode.descriptors` (R3.3) and stay in their own table (R4.20). A descriptor-only branch binds to its parent anchor at both levels — `{#A=[#B]([>])[#C]}` puts `Right` on the `[#B]` node, `{#A=N([>])C}` on the nitrogen (01a's rule); this link is the first to parse bodies with such branches, so it adds the CG-level test, and if 01b's branch path does not already anchor that way the fix is a `CgParser` change made here (iron law), not a new symbol; likewise a descriptor written before the first node of a body (`[>][#PEO]…`, F8) binds to that first node (01a's R4.2 leading rule), and if 01b's node-sequence loop has no leading-descriptor path the fix is a `CgParser` change made here, not a new symbol. The limitation that follows from flag-free dispatch — a string whose deepest level is meant to stay coarse-grained cannot be expressed — is stated in `parse_cgsmiles`'s rustdoc and in `CgLastBlockNotAtomistic`'s message. 01b's rejection of a second block disappears: `second_block_is_trailing_characters` and the `levels.len() == 1` assertion are deleted by name and replaced, in the same change, by the positive multi-block tests and by `{[#PEO][#PEO]}[#X]` → `CgExpectedBlock` (F1.10's residue case keeps a test; its kind changes) — a deliberate contract change on 01b (a string 01b rejected now parses; no string 01b accepted changes meaning).

### Name coverage has exactly one owner

`check_coverage(level, table, input)` is a private `CgParser` function, run for every level *k* for which a table `fragments[k]` exists — including F2's single atomistic table; a base-only string has no fragment table and no coverage step — raising `CgUndefinedFragment(name)` at the referencing node's span when a name in `levels[k]` is absent from `fragments[k]` (R3.4). Coverage of `levels[k]` against `fragments[k]` runs **before** `instantiate` builds `levels[k+1]`, so every missing name reaches the user as `CgUndefinedFragment` and `CgBuild` is unreachable from user input — `{[#A][#Q]}.{#A=[#X]}.{#X=CC}` → `CgUndefinedFragment("Q")`, tested. The R3.2 order-0 exemption is not implemented: 01b raises `CgInvalidBondOrder` on order-0 bonds, so the exempt case is unreachable. The converse is **not** an error — a definition never referenced stays in the table (the reference does not reject it; a shared library block is common practice). `instantiate` has no coverage branch and cannot acquire one: its signature is

```rust
fn instantiate(parent: &CGGraph, defs: &BTreeMap<&str, &CGGraph>, input: &str)
    -> Result<CGGraph, SmilesError>
```

in `cgsmiles/instantiate.rs`. The parser builds `defs` as a borrowed view of an intermediate table, whose bodies are all `FragmentBody::Graph` by dispatch, so a `Smiles` body cannot reach instantiation *by type*, and nothing is cloned. A name missing from `defs` is a reader bug, not user input: it returns `CgBuild(String)` naming the fragment, identically in debug and release (no `debug_assert!`, so the case is testable by value — the stance 01b took for `Scanner::seek`), never a panic and never `CgUndefinedFragment`.

### Instantiation semantics (R4.10 / R4.20)

For each node of `parent` in index order: look up its fragment graph, append a **disjoint copy** of that graph's nodes in body order, remap its intra-fragment edges by the copy's index offset with their `CGBondOrder` preserved, clone the descriptor lists onto the copies (R4.10), and set `parent` on every copied node to the source node's index. **No inter-copy edges are created** (R4.20) — pairing descriptors across copies is 01d's job, and inventing edges here would make 01d's contract ambiguous. Nodes carry no identity beyond their position in `nodes`, so nothing is renumbered; `parent: Option<usize>` indexes `levels[k−1].nodes` and `CGEdge.i`/`.j` index the level they belong to. `CGNode.parent` is documented as: *`None` in `levels[0]` and in every `FragmentBody::Graph` body; set — overwritten, never inherited — by instantiation*, so a body reused twice yields copies with different parents. `parse_cgsmiles` calls `instantiate` once per intermediate table, in order, appending to `levels`.

### Authority and alignment invariants — additive IR, stated in rustdoc

`CGSmilesIR` gains `fragments: Vec<BTreeMap<String, CGFragmentDef>>` beside `levels`; `CGNode` gains `parent: Option<usize>`; the new types are

```rust
pub struct CGFragmentDef { pub name: String, pub body: FragmentBody, pub span: Span }
pub enum FragmentBody { Graph(CGGraph), Smiles(SmilesIR) }
```

in `cgsmiles/ast.rs` — CG types serve one notation; `chem/` stays the SMILES/SMARTS shared vocabulary (01b). `Smiles` holds whatever `parse_fragment_smiles` returned, descriptors intact. `BTreeMap` gives deterministic iteration for diagnostics and doctests, the way the crate already keys name tables (`io/zarr/sequence.rs`, `io/data/frcmod.rs`). The rustdoc states the **authority rule**, closing off the "N+1 mutable homes" reading: `fragments[k]` is the authority for a fragment's shape; `levels[k+1]` is the expansion the notation denotes (R4.10), a derived representation produced once by the reader. `CGFragmentDef` and `FragmentBody` derive `Debug, Clone, PartialEq` like every other IR type (01b's frozen contract; 01e clones on read; `SmilesIR` already derives them). `CGSmilesIR` keeps public fields for reading (mirroring `SmilesIR`), no public constructor and no supported mutation; it is a two-list root plus its span, not a context bag. The **alignment invariant**, one test per shape: base only → `fragments.is_empty() && levels.len() == 1`; fragment blocks present → `fragments.len()` equals the number of fragment blocks and `levels.len() == fragments.len()`, because the last table is atomistic and produces no level (R1.5). **The level asymmetry is intentional and stated in the rustdoc**: levels are coarse graphs, atoms are not `CGNode`s; the last `fragments` entry holds `Smiles` bodies and no level is built from it here. Atomistic instantiation is 01d's `CGSmilesIR::to_atomistic`, which reaches a body through 01a's `fragment_to_atomistic(&SmilesIR) -> Result<(Atomistic, Vec<(AtomId, BondingDescriptor)>), SmilesError>`; 02b reads `fragments.last()`'s bodies through the same door. Neither successor needs a `CGGraph` of atoms and neither is handed a fake one; 01c calls neither function. `CGGraph` still carries no span (01b deferred it; every diagnostic here is spanned from `CGFragmentDef.span`, a `CGNode.span` or a scanner offset).

### Validation

`cgsmiles/validate.rs` follows the shape of `smiles/validate.rs`: `pub(crate) fn validate_ir(ir: &CGSmilesIR, input: &str) -> Result<(), SmilesError>` walks every level's `CGNode.descriptors` and every fragment body — `AtomNode.descriptors` of a `Smiles` body, `CGNode.descriptors` of a `Graph` body — for `DescriptorKind::Shared` and raises `CgSquashUnsupported` at the descriptor's span. The base graph is covered by the same walk, so `[!]` is refused at any level by one rule. `parse_cgsmiles` calls it after instantiation.

### Module surface

`mod cgsmiles;` stays **private** in `io/smiles/mod.rs`, exactly as `mod parser;` is; `cgsmiles/mod.rs` declares `mod instantiate; mod validate;` and, following 01b, `pub use`s the new IR types (a `pub(crate) use` there would make the outer re-export E0365); `io/smiles/mod.rs` is the single public path, gaining `CGFragmentDef` and `FragmentBody` next to 01b's exports. Everything lands under `molrs/src/io/smiles/**` behind the `smiles` feature; `io` depends on `core` + `perceive` only (`architecture-rules.md`), and nothing here reaches outside `io::smiles`. No binder impact.

### Iron law note

Three reference behaviours are knowingly not mirrored and are named in the module rustdoc: silently keeping the first of two same-named definitions (R3.1), silently skipping `{}` (R1.3), and crashing on `|n` as a body's last token (R2.24). 01b's `TrailingCharacters` guard on a second block is removed, not left in place with a workaround. `.claude/notes/notes.md` is `/mol:note`'s page; the implementation does not edit it. The `/mol:impl` summary names the recorded bend of Shape check #2 (one public door over syntax → instantiate → validate) so the orchestrator records it through `/mol:note`.

### Reuse decision

- `CgParser` (01b) — **reuse**. Block splitting, the fragment-table grammar, `check_coverage` and the body entry point are private methods on it over its existing node-sequence loop; `|n` replay keeps using `Scanner::seek` against the full input.
- `parse_fragment_smiles` (01a) — **reuse**, unchanged, for every body of the last block, including its `AtomAnnotationUnsupported` diagnostic. No atomistic re-lexing here.
- `parse_smiles` (01a) — **not used**; it rejects descriptors (`DescriptorInPlainSmiles`) and a fragment body is descriptor-bearing by construction.
- `Scanner` + 01b's `seek` — **reuse** for depth tracking, body cutting and replay; no regex, no ad-hoc `str::split`, no second cursor type.
- `SmilesError` / `SmilesErrorKind` / `SmilesError.notation` — **reuse**; additive `Cg…` variants constructed the way `CgParser` already constructs them. `CgEmptyBlock` (01b) **reused** instead of a new `CgEmptyFragmentBlock`.
- `smiles/validate.rs` — **pattern**: `cgsmiles/validate.rs` copies its shape (`pub(crate) fn validate_*(ir, input)`, private per-node walkers), not its code.
- `chem::validation::validate_ring_closures` — **not applicable**: it walks `Chain`/`ChainElement`; CG levels have no ring-closure vocabulary, and closures inside bodies are checked by the body parsers.
- `Parser` / `Dialect` in `io/smiles/parser.rs` — **new, not generalized**: `CgParser` already owns CG syntax (01b's adversarial-vocabulary argument); adding a CG dialect would put block structure inside the OpenSMILES LL(1) parser.
- `CGEdge` / `CGBondOrder` / `Span` — **reuse** verbatim; instantiation copies orders, it does not reinterpret them.
- `BTreeMap` name table — **pattern**, following `io/zarr/sequence.rs` and `io/data/frcmod.rs`.
- `instantiate`, `validate_ir`, `check_coverage`, the new `Cg…` variants — **new**: no graph-copy-and-remap routine exists in `io::smiles`, and 01b's annotation variants cannot carry the fragment-block messages without becoming ambiguous.

### Predecessor deltas this link depends on, and successor contracts it must not foreclose

01a (post-review): `DescriptorKind::{Symmetric, Left, Right, Shared}`; `parse_fragment_smiles`; branch-only descriptors bind to the parent anchor; `AtomAnnotationUnsupported(String)` in the fragment dialect for `;` inside a bracket atom (an amendment made to 01a during this link's review, so the annotation lexer has one home). 01b: the CG AST at `cgsmiles/ast.rs`, `mod cgsmiles;` private with `pub use` inside, `Scanner::seek`, `SmilesError.notation`, `CgEmptyBlock`, `CgRepeatOnRingMarker`, `CgInvalidBondOrder`. Successors: 01d adds `CGEdge.origin` (setting `Written` in `instantiate.rs`), appends `Derived` edges to the same `levels`, adds `pairs`, and reuses `CgBuild`; 02b reads `fragments.last()`.

## Testing strategy

Per `.claude/notes/testing.md` and CLAUDE.md § Testing Rules: unit tests are inline `#[cfg(test)]` modules next to the code (`parser.rs`, `instantiate.rs`, `validate.rs`, `error.rs`); there is no `molrs/tests/` tree and no `regressions/` tree in this repo, so the runnable public-API example is the rustdoc doctest in `cgsmiles/mod.rs`, executed by `cargo test --doc -p molcrafts-molrs --features full,filesystem,stream`. Fixtures are inline string literals written by hand from the grammar above — no external program produces any expected value, and nothing here is an end-to-end pipeline. Each test targets one function: the grammar and dispatch tests target `parse_cgsmiles`'s parser-side entry, the instantiation tests target `instantiate` directly, the validation tests target `validate_ir` directly, and the error-display tests target `Display for SmilesError`. Every raised kind is asserted by `matches!` on `err.kind`, never by a message substring.

- *Happy path, F2* — `{[#OH][#PEO]|3[#OH]}.{#OH=[$]O,#PEO=[$]COC[$]}`: `levels.len() == 1`, `levels[0]` has 5 nodes / 4 edges and every node `parent == None`; `fragments.len() == 1`, keys `{OH, PEO}`, both `FragmentBody::Smiles`, PEO body 3 atoms with two `Symmetric` descriptors, OH body 1 atom with one. That this parses at all is the direct proof the atomistic path uses `parse_fragment_smiles` — `parse_smiles` would return `DescriptorInPlainSmiles`.
- *Happy path, F8* — three tests: (a) `fragments[0]` holds `Graph` bodies, B1 with 2 nodes / 1 edge and `DescriptorKind::Right` on node 0, `Left` on node 1 (R3.3); (b) `fragments[1]` holds `Smiles` bodies of 3 and 2 atoms, each carrying `Right`/`Left` descriptors; (c) `levels[1]` has 6 nodes named PEO,PEO,PE,PE,PEO,PEO with parents 0,0,1,1,2,2, 3 edges of `CGBondOrder::Single` joining (0,1), (2,3), (4,5), no edge joining nodes with different parents, and each copy carrying its body's descriptors.
- *Alignment invariant* — one test per shape: `{[#A][#B]}` → `fragments.is_empty() && levels.len() == 1`; F2 → `fragments.len() == 1 && levels.len() == 1`; F8 → `fragments.len() == 2 && levels.len() == 2`.
- *Edge cases* — `{[#EO]|5}` parses with `fragments.is_empty()`; `|n` as the last token of a body; a body-level `|n` over a ring marker raises `CgRepeatOnRingMarker` with a span inside the original string (proving replay runs against the full input); a definition never referenced parses and stays in the table; `{[#OHter]}.{#OHter=[$][O-].[Na+]}` parses with one body; a body with a second `=` splits on the first only; a descriptor-only branch in a graph body (`{[#A]}.{#A=[#B]([>])[#C]}.{#B=[>]CC[<],#C=[>]CC[<]}`) attaches `Right` to the `[#B]` node and `{[#A]}.{#A=N([>])C}` attaches it to the nitrogen; F8's leading `[>]` lands on B1's first node; a body reused twice yields copies with different `parent` values; `instantiate` with a name absent from `defs` returns `CgBuild` and does not panic.
- *Must-raise, one test per fixture, named for the variant it asserts* — `{[#SC4]1[#TC5][#TC5]1}.{#SC4=Cc(c[!])c[!],#TC5=[!]ccc[!]}` → `CgSquashUnsupported` (raised by `validate_ir`, surfaced by `parse_cgsmiles`); `{[#A][#B]}.{#A=[C;0.5]C,#B=CC}` and `{[#T]}.{#T=C1=CCCC[*;s=C,0][*;s=C,0]}` → `AtomAnnotationUnsupported`, un-wrapped, at the bracket atom's span (the second also proves the entry splitter respects `[]` depth); `{[#A]}.{#A=CC,#A=CCC}` → `CgDuplicateFragment("A")`; `{[#A][#B]}.{#A=CC}` → `CgUndefinedFragment("B")`; `{[#A]}.{#A=[#X]}.{#Y=CC}` → `CgUndefinedFragment("X")`; `{[#A][#Q]}.{#A=[#X]}.{#X=CC}` → `CgUndefinedFragment("Q")`; `{[#A]}.{#A=CC}}`, `{[#A]}.#A=[$]C[$]` and `{[#PEO][#PEO]}[#X]` → `CgExpectedBlock`; `{[#A]}.{}` → `CgEmptyBlock`; `{[#A]}.{#A=}` → `CgEmptyFragmentBody`; `{[#A]}.{#A}` → `CgMalformedFragmentEntry`; `{[#A]}.{#A=[#X][#X]}` → `CgLastBlockNotAtomistic` boxing `UnexpectedChar('#')`; `{[#A]}.{#A=CC(}` → `CgLastBlockNotAtomistic` boxing `UnclosedBranch`. The two `CgLastBlockNotAtomistic` tests and the two `AtomAnnotationUnsupported` tests additionally assert `err.input` is the full string, `err.notation == Notation::CGsmiles`, the span is the inner span shifted by the body's start offset (so the caret lands on the offending token of the full string), and — for the boxed cases — the rendered message opens with the CGsmiles prefix and names the last-block rule. The squash walk is also tested directly on `validate_ir` for `{[#A]}.{#A=[!][#X]}.{#X=[$]C[$]}` (graph body) and for the base-graph `{[#A][!]}`.
- *Domain validation* — the F2/F8 counts, edge orders, descriptor placements and parent vectors above are the hand-derived expectations from R1.2 / R3.3 / R4.10 / R5.1, written as literals, derived from the grammar, not captured from the reference implementation.
- *Runnable public-API example (this repo's substitute for a regression script)* — the `cgsmiles/mod.rs` doctest parses F8 through the public `parse_cgsmiles` and asserts `levels.len() == 2`, `levels[0].nodes.len() == 3`, `levels[1].nodes.len() == 6`, `levels[1].nodes[3].parent == Some(1)` and that `fragments[1]["PEO"].body` is `FragmentBody::Smiles`. It must pass under `cargo test --doc`, which `--lib` does not run.

**Gate.** `cargo fmt --check`; `cargo clippy -p molcrafts-molrs --all-targets --features full,filesystem,stream -- -D warnings`; `cargo test -p molcrafts-molrs --lib --features full,filesystem,stream`; `cargo test --doc -p molcrafts-molrs --features full,filesystem,stream`.

## Out of scope

- Descriptor pairing, `pairs`, `EdgeOrigin`, inter-copy edges and `CGSmilesIR::to_atomistic` — 01d. This link deliberately produces levels with intra-fragment edges only; pairing during expansion was considered and rejected because pairing at an intermediate level needs the fully instantiated level that expansion is still building.
- `fragment_to_atomistic` — 01a's; 01c stores `SmilesIR` bodies and calls neither it nor `to_atomistic`.
- Any change to `parse_smiles` / `parse_fragment_smiles` / `Dialect` / `DescriptorInPlainSmiles` beyond the `AtomAnnotationUnsupported` amendment recorded in 01a — 01c is a caller only.
- Any change to `CGBondOrder`, `CGEdge`, `CgInvalidBondOrder`, `CgRepeatOnRingMarker` or `Scanner::seek` — 01b owns them; 01c exercises them from a new call site.
- Supporting `[!]` squash, weights, chirality, positional atom annotations or wildcard overloading — these raise by design in v1 (R5.5); nothing here re-scans for them or stores them, and a later spec may lift them.
- A flag or option to keep the deepest level coarse-grained — the last block is atomistic by position, documented as a limitation; a mode flag would contradict the flag-free dispatch decision.
- The R3.2 order-0 exemption for undefined names — unreachable because 01b raises `CgInvalidBondOrder`; not implemented rather than implemented-and-untested.
- A `Span` on `CGGraph` — 01b deferred it and no diagnostic in this link needs it.
- The atomistic-level fragment-table consumer (`to_fragment`) — 02b; writing / round-tripping multi-block CGsmiles to a string — no link in this chain covers it yet.
