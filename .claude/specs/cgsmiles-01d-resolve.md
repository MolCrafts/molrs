# CGsmiles descriptor resolution and atomistic expansion (link 01d)

## Summary

A `CGSmilesIR` produced by links 01a–01c knows which coarse-grained instances are bonded to which, but not *through which written bonding descriptor* — the `[$]`, `[>]`, `[<]` ports the notation hangs on nodes and on fragment bodies are still unmatched, so nothing downstream can say which atom of one fragment binds which atom of the next. This link resolves them: at parse time, every CG edge of every level is matched to a concrete pair of free, compatible ports, the match is recorded on the IR as a `ResolvedPair`, and resolving an intermediate level appends the inter-instance edges it induces to the level below. With the pairs in hand, `CGSmilesIR::to_atomistic` expands the lowest CG level into a single `Atomistic`: each node's SMILES body is converted once per fragment definition, cloned per instance, stamped with a `frag_id`, and the resolved pairs become real bonds with a real bond class. The result is topology only — elements, bonds, notation-declared properties — with no coordinates, no hydrogen repletion and no perception; the caller composes those steps.

**Pairing (resolution) rules.**

R4.6 The CGsmiles default is the BigSMILES rule: two descriptors are compatible iff, after flipping `<`↔`>` on one of them, the entire descriptor (kind, label and order) is identical [REF resolve.py:14-59 `compatible()`, `legacy=True` default at :473]: `$` pairs with `$` [DOC fragments; BIG]; `>` pairs with `<` only [DOC; BIG "bonds must form between conjugate pairs of brackets"]; `$` is orthogonal to `<`/`>` [BIG]; labels must match exactly — `{[#A][#B]}.{#A=[$a]CC,#B=[$b]CC}` produces no inter-fragment bond in the reference [REF verified]. In molrs the flip is the involution `Left↔Right`, `Symmetric↔Symmetric`, `Shared↔Shared` on the role-named kinds [INFERENCE: `Shared↔Shared` is not covered by R4.6's examples; `Shared` never reaches this link because 01c raises on it], and the order compared is the **effective** order (`None` ≡ `Single`), so `[$]` pairs `-[$]` exactly as the reference does. R4.7 A non-default first-character-only mode exists (`legacy=False`) — not v1 [REF resolve.py:37-40]. R4.9 BigSMILES's "first occurrence defines the order, later ones may omit it" is NOT implemented by CGsmiles; the order is compared every time [REF verified; BIG] — so `=[$]` does not pair `[$]`. R4.10 Every node of the level-k graph is instantiated as a disjoint copy of its fragment graph, carrying its own descriptor lists [REF resolve.py:266-315]. R4.11 Iterate the level-k edges; for an edge of order n attempt n separate bonds (`for _ in range(order)`) [REF resolve.py:336-337] — in molrs `n = edge.order.multiplicity()` (01b's `CGBondOrder`; order 0 is unrepresentable). R4.12 For each attempt, the first compatible pair by a triple nested scan: source entities in written order; target entities in written order; source descriptor list × target descriptor list; the first `(source, target, source_desc, target_desc)` wins — greedy, deterministic, no backtracking [REF resolve.py:93-104]. R4.13 Both descriptors are consumed after pairing and never offered again [REF resolve.py:346-348]. R4.14 The bond's order is the descriptor's annotated order (default 1), except 1.5 when both endpoint atoms are aromatic [REF resolve.py:350-356]; molrs states the precedence in one sentence: **an explicit symbol wins; absence between two written-aromatic ports is aromatic; everything else is single** — the Daylight rule `smiles/to_atomistic.rs:252-256` applies inside a body, so an explicit `-` between two aromatic atoms stays single (biphenyl). There is no 1.5 in molrs: `BondKind::Aromatic` maps to `BondType::Aromatic` + `BondNumber::Unknown` (`to_atomistic.rs:353,367`) because the notation declares delocalisation, not a Kekulé phase. R4.15 If no compatible pair exists the reference silently skips (`except LookupError: continue`) [REF resolve.py:344-345] — molrs RAISES `CgUnmatchableEdge { level, edge }` [INFERENCE]. R4.16 The reference iterates edges in networkx adjacency order, which for rings differs from parse order (`{[#A]1[#B][#C]1}` iterates (0,1),(0,2),(1,2)); molrs pins **parse order** and documents the atom-index difference [INFERENCE]. R4.17 Unconsumed descriptors are discarded; at the atomistic level the freed valence is filled with hydrogen during a later repletion step [DOC chirality; REF resolve.py:326-327, :431-433] — expansion drops them and adds no hydrogens. R4.18 CGsmiles needs no explicit end-group descriptors (BigSMILES does) [BIG]. R4.19 At non-atomistic levels unconsumed descriptors are just dropped [REF resolve.py:431]. R4.20 Each fragment block's descriptors are consumed exactly once at their own level; never inherited or matched across levels [REF resolve.py:402-426]. R6.2 A coarse bond of order n ≥ 2 means n distinct bonds between the two fragments, never a multiple bond: Martini cyclohexane `{[#SC3]=[#SC3]}.{#SC3=[$]CCC[$]}` → two single bonds; naphthalene as two beads uses order 3; max order 4 [DOC multiple_resolutions; REF verified]. R5.1 Atom–instance membership is recorded per atom as `fragid` by the reference [REF resolve.py:290-300]; molrs stamps `frag_id`.

## Design

### Contract deltas from predecessor reviews, assumed throughout

01a: `DescriptorKind::{Symmetric, Left, Right, Shared}`; `BondingDescriptor.order: Option<BondKind>` (`None` = no symbol written; `Some(k)` only for `Single|Double|Triple|Quadruple`, so no aromatic-order validation pass exists here); `parse_fragment_smiles`; `fragment_to_atomistic(&SmilesIR) -> Result<(Atomistic, Vec<(AtomId, BondingDescriptor)>), SmilesError>` whose map order **is** the port order (01a's `Builder` is the only walker). 01b: `CGNode` addressed by index (no `instance` field); `CGEdge.order: CGBondOrder` with `multiplicity()`; `SmilesError.notation`; the CG AST lives in `cgsmiles/ast.rs`; `mod cgsmiles;` is private and `io/smiles/mod.rs` is the single public re-export path. 01c: `fragments`, `FragmentBody`, `parent`; instantiation and validation are private steps (`instantiate.rs`, `validate.rs`) taking `input: &str`; `parse_cgsmiles` = syntax → instantiate → validate → resolve, each private, and the `CGSmilesIR` rustdoc states the invariant that an IR that exists is fully instantiated, validated and resolved (recorded decision: explicit flow beats step-splitting; sub-steps are not independently meaningful to callers).

### Data added to `cgsmiles/ast.rs`

- `pub enum PairEnd { Sub { node: usize, port: usize }, Body { instance: usize, port: usize } }`. `Sub` is an end at an intermediate level: `node` indexes `levels[k+1].nodes` (the child carrying the port) and `port` indexes that child's `descriptors`; the level-k instance is `levels[k+1].nodes[node].parent` (01c) and is also the pair's edge endpoint, so a third field repeating it would be a second copy of a fact that already has an owner. `Body` is an end at the last level: `instance` indexes `levels[k].nodes` (the node whose body holds the port — there is no child node to hang it on) and `port` indexes the map returned by `fragment_to_atomistic` for that instance's body. Two variants rather than one struct with an `Option<usize>`, because a field whose referent depends on a sibling field is a shape no reader can check.
- `pub struct ResolvedPair { pub edge: usize, pub bond: usize, pub src: PairEnd, pub dst: PairEnd, pub kind: BondKind }`. `edge` indexes `levels[k].edges` (after the append below); `bond` is which of that edge's `order.multiplicity()` bonds this is (0-based); `kind` is the resolved atomistic bond kind (R4.14). Named `kind`, not `order`, so it never reads as `CGEdge.order`, which is a count.
- `CGSmilesIR.pairs: Vec<Vec<ResolvedPair>>`, parallel to `levels`: `pairs[k]` are the pairs resolved for `levels[k].edges`, in resolution order (edge order, then bond index).
- `pub enum EdgeOrigin { Written, Derived { level: usize, pair: usize } }` and an additive field `CGEdge.origin: EdgeOrigin`. Written and derived edges stay in **one** list — a consumer that walks a level's edges must see all of them — and the tag is how provenance is recovered. Every existing construction site (01b's `parser.rs`, 01c's `instantiate.rs`, which copies a written edge into an instantiated level) sets `Written`; only `resolve` writes `Derived`. A derived edge copies the `span` of the level-k edge whose pair induced it — the only text that names that bond — so `CGEdge.span` stays total and a diagnostic on a derived edge points at the coarse bond that created it; `CgUnmatchableEdge`'s rustdoc states that rule. Its `CGBondOrder` is `Single` because one resolved pair makes one bond — a count, not a placeholder.

`ResolvedPair`, `PairEnd` and `EdgeOrigin` derive `Debug, Clone, PartialEq` (01b's frozen contract; 01e clones on read; the fixtures compare pairs by value). Descriptor lists are **never mutated** during resolution (R4.13 is a local consumed-bitmap), because `PairEnd.port` is an index into those lists and removal would invalidate every recorded pair.

### Resolution (`cgsmiles/resolve.rs`, private)

`fn resolve(ir: &mut CGSmilesIR, input: &str) -> Result<(), SmilesError>` — a private pipeline step, sibling of 01c's `instantiate` and `validate_ir`, taking `input` so every error carries the full text, a real span and `Notation::CGsmiles`. It walks levels in increasing order (R4.20 keeps namespaces per level); for each level it builds the port table (from child descriptors for an intermediate level, from the cached body map for the last level), then for each edge in **parse order** (R4.16) and each of its `order.multiplicity()` bonds (R4.11) it takes the first compatible free pair (R4.6, R4.12), marks both consumed (R4.13), computes `kind` (R4.14 precedence) and pushes a `ResolvedPair`; an unsatisfiable attempt returns `CgUnmatchableEdge { level, edge }` at the edge's span (R4.15). It then appends one `Derived` edge (`CGBondOrder::Single`, `i`/`j` from the two `Sub` ends' `node` indices, `span` copied from the level-k edge) per pair to `levels[k+1].edges`, after all written edges, in pair order, so indices already handed out stay stable, and only then resolves level k+1 (F8). Ports still free when resolution ends are dropped (R4.17/R4.19). **A level with nothing to pair against is not resolved:** a base-only IR (`fragments.is_empty()`, so the last CG level has neither child nodes nor atomistic bodies) gets `pairs[0] == vec![]` and no `CgUnmatchableEdge` — its edges stay as written, exactly as 01b's single-block fixtures require — and `to_atomistic` on it returns `CgNotExpandable` with the payload `base-only string (no fragment table)` (the wording 02b's `to_fragment` uses for the same case, so one `Display` arm serves both).

**Port lists and the fragment cache — one walker.** There is exactly one walker over a fragment body: 01a's `Builder`, reached through `fragment_to_atomistic`. The returned map is the port order, so port index and `AtomId` cannot disagree — identity by construction, not by test. `resolve.rs` defines a private `FragmentCache` keyed by definition name holding `(Atomistic, Vec<(AtomId, BondingDescriptor)>)` with `get_or_build`. It is a **per-call local**: `resolve` constructs one, fills it for the last-level port lists and drops it on return; `to_atomistic` constructs its own, fills it while cloning a body per instance and drops it on return. Within one call the conversion runs **once per fragment definition, never per instance**. What the cache is *not*: not a field of `CGSmilesIR` (the IR is a value of parse results; an `Atomistic` hanging off it would make the IR own a second representation of its own bodies), not a `static`, `thread_local` or `OnceCell`, not a memo keyed by input string across calls. Cost named twice: parsing builds one small atomistic graph per atomistic fragment definition even if the caller never expands, and `to_atomistic` builds them again — bodies are a handful of atoms, and the alternatives (a second, port-only walk; an IR that carries graphs) are the duplication and the context bag the review rejected. **Cache invariant, stated in its rustdoc:** an entry is the body exactly as `Builder` wrote it — no perception has run on it — so its `is_aromatic` stamps reflect only what the notation wrote, which is the property the next paragraph relies on.

**Written aromaticity — one predicate, and a named deviation.** `pub fn AtomSpec::written_aromatic(&self) -> bool` lands in `chem/ast.rs` (`:100-129`) as the single implementation of "the notation wrote this atom aromatic": true for `Organic { aromatic: true }` and `Bracket { symbol: BracketSymbol::Element { aromatic: true, .. }, .. }`, false otherwise (a SMARTS `a` primitive is a query, not a written aromatic atom). `Builder::add_atom_node` (`smiles/to_atomistic.rs:171-198`) asks that question in two places with two literals today; both collapse to one call, and `mark_aromatic` keeps its single job of recording the answer. **Deviation from the review decision, stated so it can be rejected:** the review asked that `resolve.rs` also *call* `written_aromatic`, but the decision that `Builder` is the only walker means `resolve` never holds an `AtomSpec` — reaching one would require re-walking the body. `resolve` therefore reads the answer `Builder` already wrote: the `is_aromatic` stamp (`to_atomistic.rs:283`) on the cached fragment `Atomistic`, which on a freshly converted body can only have come from the notation, since perception has not run on it (`from_atomistic.rs:371` already reads the same stamp). The predicate still has one implementation and one evaluator. A Kekulé-written phenyl `{[#PH][#PH]}.{#PH=[$]C1=CC=CC=C1}` therefore resolves to a `Single` inter-fragment bond — its atoms are not *written* aromatic, whatever perception would later conclude — and that case is tested beside F9 so the stamp is never mistaken for perceived aromaticity.

**Bond-kind mapping.** `bond_kind_to_type` / `bond_kind_to_number` (`smiles/to_atomistic.rs:353-377`) become `impl BondKind { pub(crate) fn bond_type(self) -> BondType; pub(crate) fn bond_number(self) -> BondNumber }` in `chem/ast.rs`, next to the enum they describe; the free functions are deleted and `:260` becomes a caller. The existing `Quadruple -> BondType::Double` approximation moves verbatim into the method rustdoc, marked as forced by `BondType` having no quadruple variant (`core/system/bond.rs:28-38`) — found, recorded, not fixed here.

### Expansion (`cgsmiles/to_atomistic.rs`)

`impl CGSmilesIR { pub fn to_atomistic(&self) -> Result<Atomistic, SmilesError> }` — a method on the type that owns the data. The free name `to_atomistic` belongs to the SMILES pipeline (`io/smiles/mod.rs:62`); there is no free alias here and the rustdoc says why. For each node of the lowest CG level, in index order: take the cached `(Atomistic, ports)` for its definition (`CgNotExpandable(name)` if the body is a `FragmentBody::Graph`), clone it, stamp every atom with `frag_id = PropValue::Int(node index)` (`PropValue` has no `UInt`, `molgraph.rs:71`; `mol_id` is carried the same way, `:1446`), then `Atomistic::merge` (`atomistic.rs:696`) into the accumulator, **keeping the returned handle map** — `merge` remaps handles, so the per-instance `AtomId`s in the port map are only valid through that map. Then for each `ResolvedPair` of the last level, translate both `Body` ends through their instance's handle map, `Atomistic::add_bond` (`:178`) and immediately, checked, `set_bond_class(bid, kind.bond_type(), kind.bond_number())` (`:206`) — `add_bond` takes no order and defaults to `Single`, so the class call is mandatory. Unpaired ports are dropped (R4.17). Every `MolRsError` from `add_bond` / `set_bond_class` / prop writes maps to `CgBuild(String)`; no `Result` is discarded on this path. The result is heavy-atom topology only: no coordinates, no hydrogen repletion, no perception; only the lowest CG level becomes atoms; intermediate `pairs[k]` exist for molpy and 02b. The `to_atomistic` rustdoc names the per-atom key `frag_id` (`PropValue::Int`, the lowest-level node index) so a caller can partition the result without reading this spec.

**`frag_id` is the only in-crate record of instance membership.** `core/system/mapping.rs`'s `CGMapping` (`bead_mask`) has zero consumers repo-wide and across the sibling repos and is **deleted** by `cgsmiles-02a-fragment-core` (the mapping capability moves to the molpy builder by operator decision), so no second home exists. The key is `frag_id`, not `mol_id` (a molecule id; CG instances are sub-molecular) nor `res_id` (a biopolymer residue; the residue/fragment vocabulary is a pending schema spec); the name mirrors the reference implementation's `fragid` (R5.1). This decision is named in the implementation summary and recorded by the orchestrator through `/mol:note` (the implementation does not edit `.claude/notes/notes.md`).

**Why resolution is parse-stage while SMILES ring closure is build-stage.** Ring closure (`smiles/to_atomistic.rs:70`) is intra-body and only means something once atoms exist, so it stays in the builder. Descriptor pairing is needed at CG levels that never become atoms — 02b's `to_fragment` and the molpy builder read `pairs` without expanding anything — so it must be finished before the IR is handed out. One sentence in `cgsmiles/mod.rs` records this; the `CGSmilesIR` rustdoc records the invariant.

### Errors

Two `SmilesErrorKind` variants added in `io/smiles/error.rs` (one error type, `Notation::CGsmiles` stamped by the reader): `CgUnmatchableEdge { level, edge }` and `CgNotExpandable(String)`, each with a `Display` arm; `CgNotExpandable`'s arm renders **`{0}: no atomistic body to expand`**, because 02b reuses the variant with a non-name payload (`base-only string (no fragment table)`) and the one arm must read correctly for both. `CgBuild(String)` — "an internal invariant of the reader was violated" — is 01c's variant (it names a fragment definition missing at instantiation) and is **reused** here for every `MolRsError` the expansion path meets; no second internal-error variant.

### Reuse decision

- `fragment_to_atomistic` (01a) — **reuse**: sole source of both the fragment graph and its port list; `Builder` is the only walker.
- `bond_kind_to_type` / `bond_kind_to_number` (`to_atomistic.rs:353,367`) — **generalize** onto `BondKind` (second real use; the natural owning type).
- The written-aromatic test inside `Builder` (`:171`, `:192`) — **generalize** into `AtomSpec::written_aromatic`, one implementation.
- `Atomistic::merge` (`:696`), `add_bond` (`:178`), `set_bond_class` (`:206`) — **reuse**; no new structural primitive on `Atomistic`.
- `CGBondOrder::multiplicity` (01b) — **reuse** as the loop bound; no second order→count mapping.
- `CgBuild(String)` (01c) — **reuse** for internal/structural failures on the expansion path; no second internal-error variant.
- `CGMapping` / `bead_mask` — **not reused** (deleted by 02a); `frag_id` is a per-atom `Int` prop like `mol_id`.
- `PendingRing` / `close_rings` (`:80`, `:324`) — **pattern** only: pending-then-match keyed on ring number inside one body vs label+kind+order across instances; a private struct, a `Cg*` variant carrying the offending index, errors built with a span.

## Testing strategy

Unit tests live in `#[cfg(test)]` modules next to the code (`CLAUDE.md` § Testing Rules); there is no `tests/` tree and no `regressions/` tree in this repo. Every expected value is hand-derived from the rules and written as a literal; no third-party chemistry software is involved at any point. Each test targets one function: `written_aromatic`, `bond_type`/`bond_number`, `resolve`, or `CGSmilesIR::to_atomistic`. String-driven cases exercise the parser+resolver; the F5 and F7 expansion cases are driven from **hand-built `CGSmilesIR` values** so `to_atomistic` is tested as its own unit.

**`chem/ast.rs`.** `written_aromatic`: `Organic { aromatic: true }` → true; `Organic { aromatic: false }` → false; `Bracket` with `BracketSymbol::Element { aromatic: true }` → true, `aromatic: false` → false; `BracketSymbol::Any`/`Aliphatic`/`Aromatic`, `Wildcard`, `Query(_)` → false. `bond_type`/`bond_number`: the whole table, including `Aromatic → (BondType::Aromatic, BondNumber::Unknown)` and the approximation `Quadruple → (BondType::Double, BondNumber::Quadruple)`. Map order: `fragment_to_atomistic("C([$]O)[>]")` returns exactly two entries in visit order — the `$` port first, the `>` port second, both on atom 0 (01a's anchor rule) — pinning that port order follows the walker, not text position.

**`cgsmiles/resolve.rs`.** F2: `pairs[0].len() == 4`, edge (OH0,PEO1) consumes PEO1's first port and edge (PEO1,PEO2) its second; no free port remains. F3: three pairs in edge order (0,1),(1,2),(0,2) with ends B0.a0↔B1.a0, B1.a1↔B2.a0, B0.a1↔B2.a1, each `kind == BondKind::Aromatic`. F4: two pairs on the one `Double` edge, bond indices 0 and 1, both `kind == Single`. F5: three pairs matching the Domain-basis step list; the two unpaired ports are BB0.C1 `<` and BB2.C0 `>` (asserted as "not present in any pair"). F6: two `Left`/`Right` pairs N(i)–C(i+1). F7: three label-forced pairs; with one label flipped → `Err` whose kind is `CgUnmatchableEdge { level: 0, edge: <the flipped edge> }` and whose `input` is the whole string. F8: `levels[1].edges.len() == 5`, the last two tagged `Derived { level: 0, pair: 0 }` and `Derived { level: 0, pair: 1 }` in that order, every earlier edge `Written`; every `ResolvedPair.edge` in `pairs[1]` indexes that final list; level-0 pair ends are `PairEnd::Sub`, level-1 pair ends are `PairEnd::Body`. F9: the four precedence outcomes plus the Kekulé spelling → `Single`. Base-only: `{[#PEO][#PEO][#PEO]}` → `pairs == vec![vec![]]` and `levels[0].edges.len() == 2`, no error. Must-raise strings: `CgUnmatchableEdge` for `[$a]`/`[$b]` and for `Right`/`Right`.

**`io/smiles/error.rs`.** `CgNotExpandable`'s `Display` renders `{0}: no atomistic body to expand` for a name payload and for 02b's `base-only string (no fragment table)` payload (both asserted; two links rely on this arm); `CgUnmatchableEdge { level, edge }` renders the level and edge indices.

**`cgsmiles/to_atomistic.rs`.** F2 → 11 atoms / 10 bonds; `frag_id` on every atom, values exactly `0..5`; the four inter-fragment bonds `BondType::Single`. F3 → 6/6 with a ring and `BondType::Aromatic` + `BondNumber::Unknown` on the three inter-bead bonds. F4 → 6/6 with both inter-bead bonds `BondType::Single`. F5 (hand-built IR) → 16/17 with BB2.C1 of degree 3. F6 → 13/12. F7 (hand-built IR) → 9/9. No atom carries a position; atom count equals the bodies' written heavy-atom count (no H added). A lowest-level `Graph` body → `CgNotExpandable`; a base-only IR → `CgNotExpandable` with payload `base-only string (no fragment table)`. One definition, three instances → the cache reports one entry / one conversion.

**Public-API example (repo convention).** This repo has no `regressions/` tree; the equivalent is the rustdoc example on `CGSmilesIR::to_atomistic`, executed under `cargo test --doc -p molcrafts-molrs --features full,filesystem,stream` (`--lib` does not run it): parse F2, `to_atomistic()`, assert the hard-coded 11 atoms / 10 bonds through public API only.

**Gate.** `cargo fmt --check`; `cargo clippy -p molcrafts-molrs --all-targets --features full,filesystem,stream -- -D warnings`; `cargo test -p molcrafts-molrs --lib --features full,filesystem,stream`; `cargo test --doc -p molcrafts-molrs --features full,filesystem,stream`.
