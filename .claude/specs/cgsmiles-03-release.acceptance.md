# Acceptance criteria

`ac-001`–`ac-006` bound the mechanical edit. `ac-001` and `ac-002` cover the two literal *forms* — the patch-level `"0.14.0"` in manifests and the minor-level `version = "0.14"` in install pins, which no single sweep can see. `ac-003` is the resolver's own opinion rather than a text match, and it is deliberately unfiltered: `cargo metadata --no-deps` returns member `molrs-python` at the python root and member `molrs` at the wasm root, so a `startswith("molcrafts")` filter would print nothing there and pass on an empty set; the with-deps run additionally exits non-zero if any of the nine path-dependency pins still requires `^0.14.0`. `ac-004` bounds the blast radius to twelve paths and twenty lines — notably excluding `molrs/Cargo.toml`, which inherits. `ac-005` encodes the lock-file reality: exactly one lock file is tracked (`.gitignore:74` un-ignores `molrs-python/uv.lock`; `:71-72` ignore the rest), so tracking is asserted with `git ls-files --error-unmatch`, which fails loudly, rather than with `git status`, which is silently empty for any ignored path. `ac-006` lists the five legitimate `0.14.0` survivors — history, a `/mol:map` stamp, and two runtime-computed `e.g.` doc lines.

`ac-007` and `ac-008` are the CHANGELOG-equivalent and its guard rail: the section names everything a consumer must read before pinning, including the two breaking changes (`SmilesError.notation` becoming required, `SmilesErrorKind` gaining variants without `#[non_exhaustive]`) and the `CGMapping`/`WeightScheme` deletion — while `ac-008` forces the one promise this release does *not* keep to be re-deferred in writing, and forbids the section from taking credit for items the chain merely noticed.

`ac-009`–`ac-012` are the iron law made checkable: green at the exact tree, numbers measured there with their feature set recorded rather than carried over (`.claude/notes/release.md:95-98` documents that failure on 0.14.0, and `:89-91` measured without `stream`, so those figures are not a baseline at all), tag equal to the SSOT and on `master`, and all three registries actually reached. `ac-013` closes the loop on both downstream repos; only when `ac-012` passes may either move.
